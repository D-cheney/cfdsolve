# OpenFOAM blockMesh 参数化结构网格

`blockMesh` 是 OpenFOAM 随附的六面体结构网格生成器。它不追求"一键贴合复杂 CAD"，其设计哲学是把网格写成**可审查、可 diff、可复现的文本**：同一份 `blockMeshDict` 在任何机器、任何受支持版本上都能生成拓扑一致的网格。对参数扫描、标准算例库、批量作业和自动化流程，这种确定性比"画得快"重要得多。当结构六面体网格与主流对齐时数值扩散低，贴壁方向又能做到很大的长宽比，因此在通道、边界层、叶栅等场景至今不可替代。

## 1 结论与适用场景

- **产出是结构化六面体网格**：单元方向由每个 block 的局部坐标决定，天然适合各向异性网格。
- **六面体的典型优势**：网格线与主流对齐时假扩散小；贴壁单元可以做得很扁（高长宽比）而不明显损失精度；相同分辨率下单元数通常比四面体省。
- **适用**：规则通道与管道、外流域基底网格、二维与轴对称楔形、平动与转动周期流道，以及作为 `snappyHexMesh` 的背景网格。
- **不适用**：复杂曲面、CAD 薄壁、含大量装配细节的几何，这些应交给 `snappyHexMesh` 或外部网格工具。
- 一句话结论：blockMesh 的难点不在"会不会写字典"，而在**块拓扑设计与分级方向**；顶点顺序与 grading 语义决定了网格是成功还是负体积。

**判断口诀**：几何能否用少量六面体块拼出来、主流方向是否清晰，是选择 blockMesh 的两个判断。能拼出来且主流顺块方向，就优先用它；拼不出来或主流复杂，才转 `snappyHexMesh`。后者表面贴合能力强，但代价是网格方向不再可控、单元数更大，边界条件与质量也更难预测。

**成本对比**：同样分辨率下，结构六面体网格的单元数通常明显少于四面体网格，梯度对齐时精度也更高；代价是分块设计耗时，几何一改往往要重设计。因此 blockMesh 最适合几何稳定、需要反复参数扫描的固定构型。

## 2 背景与原理

blockMeshDict 由五个层次组成，理清它们的关系就理解了一半工具：

1. **vertices**：所有块的角点坐标，一次列全，块之间共享同一批顶点，这是保证网格共形的关键。
2. **blocks**：每行声明一个六面体块，由 8 个顶点索引、三个方向的单元数 $(N_1,N_2,N_3)$ 和分级组成。
3. **edges**：把直边替换为圆弧、样条或折线，只改几何不改拓扑。
4. **boundary**：把朝外的面组织成 patch，并指定类型（`patch`、`wall`、`symmetry`、`cyclic`、`wedge`、`empty`）。
5. **mergePatchPairs**（可选）：合并两个内部重合面。

**块与块的连接**决定网格是否连续。两个块若共享一个面，只要公共面上的顶点完全一致、且该面两侧的单元划分满足共形要求，网格就是连续的；否则会在交界处形成非流形连接或额外界面，进而在该处产生虚假源项。因此写字典时通常先列出所有块共用的顶点，再逐块引用。`edges` 只在需要曲面或折线时出现：`arc` 给定两端点与弧上一点，`spline` 给定一串控制点，`polyLine` 用折线近似；它们改变的是几何位置而非单元数——加密仍由 `blocks` 行的单元数控制，这一点常被误解。

**为什么是六面体。** 六面体单元能沿三个方向独立布置单元数与分级，因此可以在贴壁方向放很多很扁的单元，在远场放少量接近正方的单元；网格线与主流动对齐时，格式引入的假扩散也最小。代价是**拓扑在生成前就固定**：块的连接关系必须先设计好，几何一改往往意味着重新分块。

核心在**局部坐标**。每个块都有自己的一套局部方向 $(x_1,x_2,x_3)$，由它在 `blocks` 行中的顶点书写顺序决定：$x_1$ 从顶点 0 指向 1，$x_2$ 从 0 指向 3，$x_3$ 从 0 指向 4。底面按 0-1-2-3、顶面按 4-5-6-7 逆时针书写，满足右手定则。**把 grading 分量当成全局的 x/y/z 是最常见的误解**——它与块的局部方向绑定，块一旦转向，grading 分量的含义也随之改变。顶点顺序写错，就是负体积、块翻转、面法向朝内的根源。

## 3 关键配置与公式

核心字段与取值含义：

- `convertToMeters`：坐标缩放因子，几何以毫米建模时写 `0.001`。
- `blocks ( hex (0 1 2 3 4 5 6 7) (Nx Ny Nz) simpleGrading (gx gy gz) )`：单元数与分级一体声明。
- `simpleGrading` 的每个分量是**末段单元与首段单元尺寸之比**：$g>1$ 表示沿局部正方向逐级放大，$g=1$ 为均匀分布。
- 二维案例仍是一层三维网格，前后面设 `empty`；轴对称常用 `wedge`。
- 周期面用 `cyclic`，必须满足几何平移或旋转映射条件。

分级本质是几何级数。设某方向起点单元尺寸为 $\Delta_1$、增长率为 $r$、单元数为 $N$，则第 $i$ 个单元尺寸为

$$
\Delta_i = \Delta_1\, r^{\,i-1}
$$

该方向总长与首末尺寸比为

$$
L = \Delta_1 \frac{r^{N}-1}{r-1}, \qquad \frac{\Delta_N}{\Delta_1} = r^{\,N-1}
$$

反过来，已知首末尺寸比 $R$ 与单元数 $N$，增长率由下式确定：

$$
r = R^{\,1/(N-1)}
$$

工程上先定目标首层与末层尺寸及总厚，再由 $L=\Delta_1(r^N-1)/(r-1)$ 反推 $N$，不要凭感觉填极端比值。举例：某方向长 $L=1$、取 $N=40$、要求首末尺寸比 $R=4$，则 $r=4^{1/39}\approx 1.036$，首端单元约 $0.012$、末端约 $0.046$，差距并不夸张，但已能把梯度区的分辨率提高数倍。需要**两端同时加密**时（例如通道上下壁面都要细），使用多重分级，形如 `simpleGrading (1 ((0.5 0.5 4)(0.5 0.5 0.25)) 1)`，每段给出长度占比、单元占比与展开比。除 `simpleGrading` 外，`blocks` 行还接受 `cellRatio` 形式的展开比，或对每条边单独指定的 `edgeGrading`；当块形状不规则、或希望不同侧面各自分级时用后者。由目标尺寸反推单元数时，可由总长 $L$ 与首端尺寸 $\Delta_1$ 求解：

$$
N=\frac{\ln\!\left(1+L(r-1)/\Delta_1\right)}{\ln r}
$$

据此在动手前评估单元数是否会导致过大的长宽比或过高的总网格量。

## 4 工程做法与参数

- **先画拓扑草稿再写字典**：在纸上给每个块编号、标出共享顶点，能避免绝大多数连接错误。
- **单元展开比**：单块内相邻单元尺寸比建议 $\leq 1.2$，最多不超过 1.3；相邻块在公共面上的单元分布要尽量连续，否则接口处会出现截断误差突跃。
- **公共面一致性**：相连的块在共享面上顶点顺序相反、单元数相同或成整数比，否则会出现非流形连接或台阶。
- **长宽比预算**：核心区单元长宽比一般控制在 100 以内；贴壁单元可达数百甚至上千，但流向与展向尺寸要同步缩放，避免单元过于"细长如针"。
- **单位检查**：`convertToMeters` 与顶点数值必须搭配同一套单位，否则几何整体放大千倍却不报错。
- **边界命名**：`boundary` 中的 patch 名必须与 `0/` 下各场文件以及 `constant/` 设置一致，改名要同步全工程。
- **验收**：生成后先用 `checkMesh` 看拓扑，再在 ParaView 中核对块连接、法向、局部尺寸跳变与边界名称；随后对目标工程量做系统加密，确认结果稳定。
- **分块策略**：对带弯折或台阶的几何，先用少量块把计算域切成规则子域（入口段、转弯段、出口段），在公共面上让单元正交对齐；转角处不要用单个块硬掰，否则单元会严重偏斜。块数不是越多越好，能简洁表达就不硬拆。
- **朝向与非正交**：块的边若与几何边界和主流方向夹角过大，生成出的单元面与单元连线夹角随之增大，非正交度上升，扩散项修正量增加。设计时应让块的边尽量贴近边界与主流方向，必要时在转角处增加块数，把夹角摊薄到可接受范围。
- **单元数估算**：总单元数等于各块单元数之和；贴壁加密时法向层数往往主导总量，动手前先确定核心区单元尺寸与贴壁层厚，避免生成后才发现内存不足。

## 5 可复现示例

一段可直接复用的三维通道基底网格（流向长 10、高 1、展向 0.1，y 向向两侧壁面加密）：

```text
FoamFile
{
    version     2.0;
    format      ascii;
    class       dictionary;
    object      blockMeshDict;
}

convertToMeters 1;

vertices
(
    ( 0 0 0.0) (10 0 0.0) (10 1 0.0) ( 0 1 0.0)
    ( 0 0 0.1) (10 0 0.1) (10 1 0.1) ( 0 1 0.1)
);

blocks
(
    hex (0 1 2 3 4 5 6 7) (100 40 1)
    simpleGrading (1 ((0.5 0.5 4)(0.5 0.5 0.25)) 1)
);

edges ();

boundary
(
    inlet  { type patch; faces ((0 3 7 4)); }
    outlet { type patch; faces ((1 5 6 2)); }
    wall   { type wall;  faces ((0 4 5 1)(3 2 6 7)); }
    front  { type empty; faces ((0 1 2 3)); }
    back   { type empty; faces ((4 7 6 5)); }
);

mergePatchPairs ();
```

若要表示曲面边，可在 `edges` 中改直边为圆弧，例如把顶点 1-5 之间改为 `arc 1 5 (10.5 0.2 0.05);`，中点是圆弧上的插值点。生成与检查命令：

```bash
blockMesh -case . | tee log.blockMesh
checkMesh -allGeometry -allTopology | tee log.checkMesh
```

若要做三维展向，只需把展向单元数改为大于 1 并去掉 `empty` 面。命令选项随版本略有差异，以本机帮助为准。

## 6 常见坑与排查

- **负体积或块翻转**：顶点顺序不满足右手定则，先核对 0-1-2-3 与 4-5-6-7。
- **grading 方向反了**：把局部方向当全局方向，加密加到了不该加密的位置。
- **公共面台阶**：相邻块单元数不成整数比，公共面出现非共形连接。
- **块之间顶点不共享**：本应重合的顶点坐标却不一致，生成裂缝或重叠面。
- **单位错位**：顶点用毫米、`convertToMeters` 却是 1，几何放大千倍。
- **二维未设 empty**：忘记把前后设成 `empty`，厚度方向也被求解，出现虚假三维效应。
- **patch 名不同步**：改了 `boundary` 名字，`0/` 场文件仍用旧名，求解器报找不到 patch。
- **只信 checkMesh 通过**：拓扑合格不代表关键区分辨率足够，务必回看目标区的实际单元尺寸。
- **块数过多难维护**：能用少量块表达就别硬拆，过度分块反而增加顶点与公共面出错的机会。
- **把 `edges` 当加密手段**：以为改成 `arc` 或 `spline` 会加密，实际加密只由 `blocks` 的单元数决定。

## 7 检查清单与参考

1. 每个块的顶点顺序是否满足右手定则？
2. grading 分量是否按块的局部方向理解？
3. 相邻块公共面顶点顺序与单元数是否共形？
4. `convertToMeters` 与顶点数值是否匹配同一单位？
5. 二维与轴对称的前后面是否正确设为 `empty` 与 `wedge`？
6. 核心区与贴壁区的长宽比是否在预算内？
7. patch 名是否与 `0/` 及 `constant/` 一致？
8. 是否用 `checkMesh` 与 ParaView 双重核对，并做了网格敏感性分析？
