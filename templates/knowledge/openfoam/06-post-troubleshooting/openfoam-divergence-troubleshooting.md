# OpenFOAM 发散、浮点异常与结果异常排查

排错的目标始终是同一个：找到"第一个失去物理合理性的量"，而不是最后触发崩溃的那个方程。压力求解器报错，根因可能出现在更早的温度、密度、相分数或网格上；求解器只是在最后一刻替你承受了错误。本文给出一条可复现、分层、且能留下证据的排查路径。

## 1 结论与适用场景

先把原则摆清楚：

- 先定位，后修复。任何"直接改松弛再试"的做法都在抹掉定位信息。
- 排查按物理输入 → 边界 → 网格 → 时间步 → 物性 → 数值设置的顺序推进，不跳步。
- 浮点异常（floating point exception）几乎总是"除零、溢出、开方负数或 NaN 传播"的表象，根因在更早的场值里。
- 缩短写出间隔、保存首个异常前后的场，是把"偶发崩溃"变成"可复现问题"的关键。
- 临时稳定措施（降时间步、加大松弛、降阶格式）可以用来跨过启动阶段，但必须随后恢复目标精度并做敏感性验证。

适用场景包括：残差爆炸并报浮点异常、场里出现 NaN 或极大值、出现 `bounding` 消息、以及"没崩但结果明显错误"的隐性失败。

## 2 背景与原理

OpenFOAM 崩溃前通常有一串前兆消息，读懂它们比读最后的堆栈更有效：

```text
--> FOAM Warning : ... 
bounding k, min: -1.2e+08 max: 4.5e+12 average: 3.1e+09
#0  Foam::error::printStack(...)
#1  Foam::sigFpe::sigHandler(int)
```

`bounding` 表示有界格式把越界场值强行裁剪回允许范围，这是**症状**：它说明上一次求解已经产生了非物理值。随后出现的 `sigFpe` 只是这个非物理值在下一处除零或开方时引爆的结果。因此追根溯源要从 `bounding` 的第一个变量、第一个时间步开始。常见的浮点异常来源可分为四类：分母趋零（体积、密度、湍流耗散率、相分数）、溢出（指数、幂次、反应速率）、开方或对数负数（湍流量、温度），以及 NaN 在场间传播。它们几乎都不是求解器本身的缺陷，而是上游输入与网格的后果。

另一个容易被忽略的机制是非正交修正。当网格非正交度高时，压力方程会引入显式的非正交修正项，其系数随非正交角增大而放大，在耦合强、时间步大时容易引起震荡；这也是为什么“先把网格质量做好”往往比反复调松弛更有效。

稳定性的数学来源有几条主线。显式/半隐式时间推进受 Courant–Friedrichs–Lewy 条件约束：

$$
\Delta t \leq Co_{max} \frac{\Delta x}{\left| \mathbf{u} \right|}
$$

它说明时间步必须随最小单元尺寸和最大速度一起缩小。对方程做欠松弛时，更新式为

$$
\phi^{n+1} = \phi^n + \alpha \left( \phi^{*} - \phi^n \right)
$$

其中 $\alpha \in (0,1]$ 是松弛因子。$\alpha$ 越小越稳定，但对解的推进也越慢；把 $\alpha$ 压到极小只会掩盖问题，不会消除问题。

网格质量通过离散系数直接进入稳定性。单元 Peclet 数衡量对流与扩散的相对强弱：

$$
Pe_{\Delta} = \frac{\left| \mathbf{u} \right| \Delta x}{\nu}
$$

当 $Pe_{\Delta} > 2$ 时，中心差分对流格式失去有界性，残差容易震荡。对瞬态扩散主导问题，网格 Fourier 数给出另一条约束：

$$
Fo = \frac{\alpha_{diff} \Delta t}{\Delta x^2}
$$

这里 $\alpha_{diff}$ 是热扩散率。$\Delta x$ 过小或 $\Delta t$ 过大都会让 $Fo$ 越界，使扩散项显式处理时发散。这些判据共同说明：发散往往不是"数值参数没调好"，而是网格尺度、时间步与物理量级三者不匹配。

## 3 关键配置与公式

第一层防线是时间步。对瞬态问题在 `system/controlDict` 中启用自动时间步并设上限：

```cpp
deltaT          1e-5;
adjustTimeStep  yes;
maxCo           1.0;
maxDeltaT       1e-3;
```

`maxCo` 保稳定，但不会替你把物理过程分辨清楚，因此还要设 `maxDeltaT` 防止 Courant 很小时步长被放得过大。对旋转机械、动网格或多相界面，应改用 `maxAlphaCo` 等专用判据。

第二层防线是欠松弛。在 `system/fvSolution` 中显式给出，避免默认值随版本漂移：

```cpp
relaxationFactors
{
    equations
    {
        U       0.7;
        k       0.7;
        omega   0.7;
        e       0.9;
    }
    fields
    {
        p       0.3;
    }
}
```

压力取 0.3 左右、动量取 0.5～0.8、能量取 0.8～1.0 是稳健的起步区间。耦合或伪瞬态求解则用 Courant 数控制，通常从 1～5 起调。

第三层防线是有界与格式。对流项优先选择有界格式，必要时临时降到一阶迎风以跨过启动冲击，但要在收敛后恢复并重算。`fvSchemes` 中的 `limitedLinear`、`vanLeer` 等限制器通过约束面值来防止过冲。若能量或组分方程在启动阶段震荡，可先检查对流格式是否无界、以及扩散项系数量级是否异常。

需要强调的是，这三层防线是“保稳定”的手段，不是“代替排查”的手段。它们的正确用法是：先用它们把求解带过启动瞬态，再在稳定后确认根因是否已经消除。若根因仍在，一旦放宽任何一层，问题就会重现。

## 4 工程做法与参数

**固定复现。** 保留原始案例与日志，复制到诊断分支；把写出间隔缩短到每步或每几步一次，确保首个异常前后的场被完整保存。记录版本、核数与启动命令，必要时用串行短算排除并行分解与通信带来的因素。

**二分定位。** 逐项关闭新增的物理：化学反应、辐射、相变、源项、动网格或用户代码。每次只改一个因素，并维护"成功/失败矩阵"，把影响范围收缩到最小集合。用更简单的模型先验证基础流场，再逐步加回复杂物理。

**边界根因清单。** 边界是发散最集中的来源，重点核对：patch 名是否与网格一致；压力基准（`pRefCell`/`pRefValue`）是否设置且位于合理位置；入口与出口是否配对，出口是否放到了回流区；混合边界（`inletOutlet`、`pressureInletOutletVelocity`）回流值是否给定；壁面与对称面是否误用；周期性边界两侧几何是否真正匹配。

**网格根因清单。** 运行 `checkMesh`，关注最小正交性、最大长宽比、非正交修正与负体积单元，并确认最差单元是否正好落在强梯度或强源项区。若最差单元位于关键区，应优先局部加密与光顺，而不是靠降阶格式硬压。

**物性与初始场根因清单。** 核对单位与量纲、坐标方向、物性数量级；检查温度、密度、湍流量、相分数与组分是否处处物理可实现（无负绝对温度、无负密度、无越界相分数）。用 `setFields` 初始化时确认区域选择与赋值方向。

**并行与分解因素。** 若串行短算不复现，才回头查并行：分解后各子域是否包含完整边界、处理器的负载是否均衡、耦合面通信是否正常。跨子域的强源项或旋转区容易被切到单个进程而引发局部失稳，适当增加分解方向或换成 `scotch` 往往能缓解。

**识别“假收敛”。** 当残差在某个不小不大的量级上平住、目标量也不再变化时，不要急于宣布成功。真正的收敛应同时满足质量守恒、目标量平台与场量物理合理；若只满足“残差不动”，很可能是求解被裁剪或松弛压住，掩盖了错误。

## 5 可复现示例

串行复现并逐步缩小写出间隔，是最有效的第一动作：

```bash
cp -r case case.debug && cd case.debug
sed -i 's/writeInterval.*/writeInterval   1;/' system/controlDict
```

```bash
checkMesh -allGeometry -allTopology > log.checkMesh 2>&1
grep -E "Failed|non-orthogonality|Max aspect ratio|negative" log.checkMesh
```

```bash
foamRun -case . > log.run 2>&1 || echo "EXIT=$?"
tail -n 80 log.run
```

定位"首个异常时间步与字段"的伪代码：

```text
输入: 每个写出时刻的场 (U, p, T, k, ...) 以及日志
对时间 t 递增:
  读取该时刻各场的 min/max
  若 任一场出现 NaN/Inf 或超出物理界:
      记录 (t, 首个越界字段, 越界单元位置)
      停止 —— 这是根因候选，而非最后崩渍的方程
若 无越界但日志报 FPE:
      回看该时刻前的 bounding 消息，取其首个变量
```

一个具体例子：某可压缩案例在 `Time = 0.0032` 报浮点异常。回看日志发现上一步先出现 `bounding T, min: -40`，说明能量方程已经产生负绝对温度；继续追查发现入口总温边界给成了静温、且时间步偏大。把入口改用总温、`maxCo` 降到 0.8 后问题消失——若一开始就去调压力松弛，只会推迟崩溃而找不到根因。

## 6 常见坑与排查

- **只降松弛不找根因**：$\alpha$ 越小越稳，但错误物理输入依旧存在，只是延后爆发。
- **把 `bounding` 当噪声**：它是有界格式在报警，第一个被裁剪的变量往往就是根因。
- **在并行下直接调试**：并行分解与通信会掩盖串行才暴露的问题，先用单核短算复现。
- **覆盖式重定向日志**：多次运行写同一个文件，会丢掉唯一能定位首个异常的证据。
- **忽略出口回流**：错误出口边界的回流值会让内部流场在几步内被污染。
- **用极低阶格式长期运行**：结果"稳定"但数值扩散巨大，属于另一种失败。
- **忽略"收敛但错误"**：没有崩溃也可以错。若质量不守恒、流向与压差矛盾、温度超出能量界限、或结果对微小设置极敏感，应按同一流程诊断。

排查顺序：① 单位、量纲、坐标方向与物性数量级；② patch 名、压力基准、进出口配对与回流值；③ `checkMesh` 最差单元及其位置；④ 初始场可实现性与区域选择；⑤ 最大/平均 Courant 数与局部速度热点；⑥ 温度、密度、湍流量、相分数、组分的最小最大值；⑦ 源项、旋转、动网格与用户代码；⑧ 最后才调整格式、松弛、容差与校正次数。

## 7 检查清单与参考

检查清单：

1. 是否复现了"首个失去物理合理性的量"，并记录了时间步与位置？
2. 是否保留原始案例、独立诊断分支与未被覆盖的日志？
3. `checkMesh` 最差单元是否位于关键区，是否需要局部加密？
4. 每条边界是否都有明确物理含义、配对关系与合理的回流处理？
5. 时间步与 Courant 数是否满足所选格式的稳定性要求？
6. 松弛因子与格式是否显式给出、而非依赖默认值？
7. 临时稳定措施之后，是否恢复了目标精度并做了敏感性分析？
