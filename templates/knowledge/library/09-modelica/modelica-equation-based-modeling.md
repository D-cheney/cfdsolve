# Modelica 方程式建模与模型平衡

Modelica 用方程而不是赋值描述物理关系，工具据此决定求解顺序。这意味着建模者的任务不是“写算法”，而是把物理守恒与构成关系忠实地写成方程，并保证模型结构平衡。理解平衡，往往是区分“能跑”和“物理正确”的分水岭。本文从守恒关系出发，说明如何构造可组合、可检查的组件，以及如何用平衡检查定位结构错误。

## 1. 结论与适用场景

写组件时先问两件事：模型里有哪些变量、哪些方程。平衡的基本要求是方程数与未知量数相等，且结构上可解。若不等，模型要么欠定（无法确定状态）、要么过定（约束冲突），都应在建模阶段发现，而不是等到求解器报奇异。

- 声明式方程适合表达守恒与构成关系：质量、动量、能量平衡，以及物性、传热关联式。
- `algorithm` 适合确有顺序的流程（查表插值、迭代、分段逻辑），但会隐藏方程结构，应尽量少用。
- `function` 适合可复用的纯计算，输入输出明确，不参与全局方程系统，也不会污染平衡。
- 参数化组件应把物理参数（体积、换热系数、阻力系数）暴露为 `parameter`，把状态与代数变量交给方程确定。

判断“该用方程还是算法”的准则是：如果关系本身是“物理上同时成立”的，用方程；如果关系天然是“先算 A 再算 B”的，用函数或算法。把物理上无先后之分的关系写成算法，会让模型失去可组合性和可检查性。

对 CFD 与热流体工程而言，这一准则几乎总能落地：流动与传热的守恒、压降与流量的构成关系、物性与状态方程，都是天然的方程；而查表、迭代求解某个隐式关系、按开关选择关联式，则更适合封装成函数或算法。把两者分清，模型会既清晰又稳定。

## 2. 原理与协议/语义

方程表达的是“表达式相等”，而不是赋值。`a = b + c` 与 `b = a - c` 在语义上等价，工具会挑选数值上最稳妥的方向求解。这种无因果（acausal）特性使组件可以复用、可以反向连接，但也要求模型在结构上自洽：任何一处约束的重复或缺失，都会在整体结构中暴露。

变量角色需要分清：`parameter` 与 `constant` 在一次仿真中固定；普通变量可能是代数变量，也可能是状态变量；带 `der(x)` 的变量参与微分方程。是否成为状态由工具的状态选择决定，通常与储能元件（质量、能量、动量）对应。理解这层对应，才能在报错时判断是哪个储能元件的方程写错了。

系统整体是一个微分代数方程组（DAE）。`connect` 语句会生成连接方程并计入平衡，因此组件内部看似“不平衡”是正常的，组合后由连接方程补齐。结构分析（匹配与排序）由工具完成：它把方程与未知量配对、展开连接方程、必要时做指标约减。建模者的任务是让结构分析能顺利通过，而不是替工具决定求解顺序。

结构分析通常分两步：匹配（matching）把每个方程指派给一个未知量，排序（sorting）再决定求解顺序。若匹配失败，说明存在结构奇异——往往意味着某组方程无法确定某个变量，或同一变量被过度约束。工具报出的“欠定/过定”正是匹配失败的具体表现，理解这一点就能把模糊报错翻译成明确的建模缺陷。

指标（index）是另一层信息。理想情况 DAE 是指标 1，即代数约束不隐含状态导数；当连接或构成关系导致对代数量的约束需要求导才能解出状态时，指标升高，求解更困难。常见诱因是把两个守恒关系写成同一个量的不同表达式，或直接给定某个本应由微分方程决定的量。

还有一点常被忽视：函数与方程可以混用，但要清楚边界。函数内部是命令式计算，返回纯结果；方程内部是声明式关系，参与全局求解。把本该是方程的关系写进函数，会让耦合信息丢失，因为函数调用在结构分析中被视为黑箱；反之把有顺序的流程写成方程，会造成不必要的隐式耦合与求解困难。

## 3. 关键公式与接口

一般 DAE 可写为残量形式

$$ F(t, x, \dot{x}, y) = 0, \qquad x(t_0) = x_0 $$

其中 $x$ 是状态、$y$ 是代数变量。结构平衡要求未知量数与方程数相等：

$$ N_{var} = N_{eq} $$

更严格地，还要求代数部分的雅可比非奇异：

$$ \det\left(\frac{\partial F}{\partial y}\right) \neq 0 $$

自由度可用来快速判断模型是否可解：

$$ N_{dof} = N_{var} - N_{eq} $$

$N_{dof} > 0$ 表示欠定，$N_{dof} < 0$ 表示过定，两者都需要修正。需要强调，$N_{var}=N_{eq}$ 只是必要条件：结构平衡后仍可能因雅可比奇异而无法求解，例如两条方程在数值上线性相关。因此平衡检查应与求解试验结合，平衡通过不代表物理正确，只代表方程数目对得上。把自由度检查当作日常习惯，能在结构层面快速定位大多数“求解不动”的问题。指标（index）衡量求解难度：若 $\partial F/\partial \dot{x}$ 可逆，通常为指标 1；不可逆则需要指标约减或补充独立约束。稳态或初始条件常用

$$ \dot{x} = 0 $$

表达，但它只应施加在真正处于平衡的状态上，盲目施加会造成约束冲突。

## 4. 工程做法与参数

- 从守恒出发：先写质量、能量、动量平衡，再补构成关系，最后加接口，方程自然成形。
- 小模型验证：先把每个组件单独与已知边界条件拼成最小算例，确认平衡与量级，再进系统。
- 显式单位：所有变量与参数标注 `unit`，工具即可做量纲检查，提前暴露单位错误。
- 变量与方程计数：开启工具的结构报告，核对方程数与变量数，定位不平衡来源。
- 慎用 `algorithm`：它隐藏方程，破坏平衡可见性；确有顺序需求时，把纯计算下沉到函数。
- 参数而非魔法数：把可标定量暴露为 `parameter`，便于辨识、复用与批量扫描。
- 合理断言：用 `assert` 检查物理边界（压力为正、温度在合理区间），把错误提前到运行期可见。
- 自顶向下再自底向上：先画系统连接草图确认接口，再逐组件补方程，避免遗漏。
- 结构测试用例：为每个组件准备一组边界条件，使其能独立跑通并给出已知量级的结果。
- 增量构建：先让单组件通过，再逐条连接并重新检查平衡，把结构错误扼杀在最小范围内。

## 5. 可复现示例

一个最小热容—热源模型的平衡示例：

```modelica
model ThermalMass
  parameter Modelica.Units.SI.HeatCapacity C = 1000;
  parameter Modelica.Units.SI.Temperature T_env = 293.15;
  parameter Modelica.Units.SI.ThermalConductance G = 5;
  Modelica.Units.SI.Temperature T(start = 300);
  Modelica.Units.SI.HeatFlowRate Q_flow;
equation
  C * der(T) = Q_flow;                     // 能量平衡
  Q_flow = G * (T_env - T);                // 构成关系(牛顿冷却)
end ThermalMass;
```

该模型有未知量 $T$ 与 $Q_flow$，方程两条，自由度为零。用命令行可以快速查看结构平衡摘要：

```bash
# 伪命令: 打印结构平衡摘要(不同工具子命令名可能不同)
omc --show-balance ThermalMass.mo
# 期望: unknowns = 2, equations = 2, states = 1 (T)
```

验证：把 $T$ 的初值分别设为高于与低于 $T_env$，$T$ 应单调趋向 $T_env$ 且守恒量合理；把 $G$ 改大，收敛应更快。若工具报“方程数与变量数不匹配”，按第 6 节的顺序排查。

进一步，可以故意制造一个欠定模型（去掉一条方程），观察工具报出的自由度与变量，验证自己确实理解了平衡检查的含义。这种“反向测试”对掌握结构诊断尤其有效：当你真正遇到工具的平衡报错时，能立刻判断是缺方程、多方程，还是单位与参数的问题。

## 6. 常见坑与排查

- 计数不匹配：方程数与变量数不等，多为漏写方程或重复定义变量。
- 用 `initial equation` 掩盖平衡错误：初始化方程只在初始化阶段生效，不能替代运行期缺失的方程。
- 隐藏的指标 2：直接把某个代数约束求导当作补充方程，会抬高指标，宜改用物理上独立的约束。
- 忽略连接方程：只看单组件平衡，忘记 `connect` 会补齐方程，误判为不平衡。
- 单位缺失：无 `unit` 则量纲错误无法自动发现，只能靠人工核对。
- 过度使用 `algorithm`：把本可写成方程的关系塞进算法，破坏平衡可见性与可组合性。
- 重复定义：同一变量被两条方程约束，导致过定或矛盾。
- 结构平衡但数值奇异：雅可比在初值处奇异，求解器报错；检查是否存在线性相关的方程或退化的参数。
- 参数问题伪装成平衡问题：参数缺失或量级离谱导致初始化失败，但结构其实平衡；先看结构报告，再调参数。

诊断顺序：打开结构报告 → 核对变量/方程计数 → 检查 `connect` 补方程 → 检查重复约束 → 检查指标 → 检查单位。

## 7. 检查清单与参考

检查清单：
1. 模型有明确的物理守恒基础；
2. 方程数与未知量数在组合后相等；
3. 代数部分雅可比非奇异；
4. 关键变量与参数都标注单位；
5. 纯计算下沉到函数，少用 `algorithm`；
6. 用最小算例验证过平衡与量级；
7. 物理边界有 `assert` 保护；
8. 初始化方程没有掩盖运行期结构错误。
