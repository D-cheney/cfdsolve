# Modelica 连接器、连接方程与能流方向

在 Modelica 里，组件之间不是靠“赋值连线”，而是靠连接器（connector）与 `connect()` 生成方程来耦合。理解这一点，是理解整套语言可组合性的关键：同一个组件可以改变连接方向、接入不同网络而无需改写内部方程，靠的正是连接器背后的守恒语义。本文聚焦连接器如何生成守恒方程、能流方向如何约定，以及这套机制在流体与热网络中的正确用法与校核方法。

## 1. 结论与适用场景

当你要连接两个物理组件时，先问一句：接口上哪些量必须相等、哪些量必须守恒。`connect(a, b)` 不是把 `b` 的值赋给 `a`，而是根据变量前缀生成两类方程：普通变量在连接点相等，`flow` 变量在连接集合中代数和为零。写对连接器，组件才具有方向无关的可组合性。

- 势变量（potential）：压力、温度、电压、位移等，连接后相等，代表“驱动势”。
- 流变量（flow）：质量流量、热流率、电流、力等，连接后代数和为零，代表“守恒流”。
- 流变量（stream）：随质量流携带的比焓、组分等，用于正确计算反向流动时的混合值。

这套约定在流体网络中尤其重要：有了它，一个“容积”组件不必知道自己上游是泵还是阀，只要接口约定一致就能拼装。若用普通变量表示流量、或用 `=` 手工传递流量，就会破坏自动守恒，网络的总质量不再守恒却不报任何错误——这类错误往往在结果里表现为缓慢漂移，很难当场察觉。

反过来说，连接器的设计质量直接决定模型库的可复用性。一个理想的连接器应当“方向无关、单位完整、语义自明”：使用者无需查手册就能推断哪些量相等、哪些量守恒。当连接器语义含混时，组件之间的耦合会变得脆弱，任何一处修改都可能破坏守恒，而这类错误往往不会抛出异常，只会让结果悄悄偏离。因此连接器既是物理接口，也是模型库的契约。

## 2. 原理与协议/语义

连接是把若干连接器归入一个连接集合（connection set），并对集合生成方程。对势变量，集合内两两相等；对 `flow` 变量，集合内所有流之和为零。生成规则与连接方式（星形、链形、多端）无关，只要在同一个集合内，方程就一次生成。这也是为什么连接顺序不影响结果——方程是同步满足的，而不是逐步执行的。

符号约定是守恒成立的隐含前提。Modelica 约定 `flow` 变量的正方向为“流入组件”。连接器图标上的箭头、组件内部方程里的流量符号、以及工具求和时的符号，必须全部一致，否则质量或能量会以错误符号参与平衡。改成“流出为正”也能工作，但整条链上的组件都要统一，混用必然出错，而且错误常常只在多分支网络里才暴露。

从代数角度看，连接方程是线性约束，加入系统后并不改变未知量的数量，只提供等量的方程，这正是“连接不引入自由度”的严格含义。也正因为连接是方程而非赋值，多条连接语句可以叠加，工具会自动合并同一连接集合并统一生成方程。若把组件声明为可扩展连接器（expandable connector），连接集合还能在组合时动态增长，适合总线式的信号汇总。

`stream` 变量解决的是“混合值”问题。当两股温度不同的流体在某节点汇合，节点处的比焓并不是两股焓的简单平均，而应按质量流量加权。`stream` 语义让工具在可能反向流动时自动选择上游值并做守恒加权，从而在正流与反流之间保持连续。若把比焓写成普通变量直接相等，反向流动时会得到物理错误的结果。因此凡是可能双向流动的流体接口，都必须用 `stream`。

还有一层是能流方向。能量在连接中的传递方向由流变量的符号隐含决定：某节点净功率为零，意味着输入功率等于输出功率。因此压力—焓接口必须成对定义：给出压力（势）和焓流（流），组件才能既传递驱动势又传递能量率。只给温度而不给焓流，会丢掉流量信息，能量无法闭合，热耦合的结果也就失去意义。

## 3. 关键公式与接口

设一个连接集合包含 $n$ 个连接器的同一对变量。对势变量 $v$，连接生成相等方程：

$$ v_1 = v_2 = \cdots = v_n $$

对同名的流变量 $\dot m$，连接生成守恒方程：

$$ \sum_{k=1}^{n} \dot m_k = 0 $$

这两类方程合起来，恰好为集合内 $n$ 个标量未知量提供 $n$ 个方程：

$$ (n-1) + 1 = n $$

这就是连接不引入欠定或过定的结构原因。若某个变量被误声明为普通变量，集合内就只剩 $n-1$ 个方程，出现自由度和守恒的缺失，质量会在网络中凭空产生或消失。

把这一计数推广到整个网络：每个连接集合都维持变量数与方程数的平衡，因此组合任意多个组件后，系统仍然结构平衡。这正是 Modelica 能够“即插即用”的代数基础——守恒是自动的，前提是每个接口都正确声明。因此，判断一个网络是否守恒，可以退化为检查其每个连接集合是否都按势/flow 规则生成方程，而不必逐条推导守恒式。

`stream` 混合按质量流量加权求上游值。对多股汇合节点，流出比焓为

$$ h_{out} = \frac{\sum_{i} \max(\dot m_i,\,0)\, h_i}{\sum_{i} \max(\dot m_i,\,0)} $$

对一般流体，节点能量的净流率可写为

$$ \dot E = \sum_{k} \dot m_k \left( h_k + \frac{1}{2} c_k^{2} + g z_k \right) $$

而单个容积的质量平衡为

$$ \frac{dM}{dt} = \sum_{k} \dot m_k $$

上述几式共同构成流体网络守恒的核心：势相等给驱动，流量求和给质量守恒，焓流加权给能量与组分的正确混合。

## 4. 工程做法与参数

- 连接器命名统一：势变量与流变量成对出现（如 `p` 与 `m_flow`、`T` 与 `Q_flow`），单位标注齐全，避免同名不同义。
- 符号一致：全库统一“流入为正”，并在文档字符串中写明，减少换人维护时的错误。
- 避免过约束：不要在同一连接上同时强制两个势变量或两个流量；压力—流量接口一端给定即可。
- 正确使用 stream：流体连接器用 `stream` 声明比焓与组分，让工具处理反向流混合，不要手工在内部加权。
- 多组分处理：组分用质量分数向量配合 `stream` 语义，保证各组分的质量守恒，而不仅是总质量。
- 验证守恒：对每个网络算例校核总质量与总能量的收支，确保连接方程确实在起作用。
- 方向无关测试：把组件反过来接，结果应完全一致，否则连接器设计存在方向依赖缺陷。
- 参数化环境量：把参考压力、参考温度等环境量作为参数在所属组件中统一，避免两侧默认值不同。
- 文档字符串：为连接器与每个变量写清含义、单位与正方向，使接口自解释。

## 5. 可复现示例

定义一个流体连接器与两个容积组件，用 `connect` 组成网络：

```modelica
connector FluidPort
  Modelica.Units.SI.Pressure p;
  flow Modelica.Units.SI.MassFlowRate m_flow;
  stream Modelica.Units.SI.SpecificEnthalpy h_outflow;
end FluidPort;

model Volume "集总容积"
  parameter Modelica.Units.SI.Volume V = 0.01;
  Modelica.Units.SI.Pressure p(start = 1e5, fixed = true);
  FluidPort port;
equation
  V * der(p) / (287.0 * 300.0) = port.m_flow;   // 理想气体简式
  port.p = p;
  port.h_outflow = 1.0e5;                      // 简化: 常数比焓
end Volume;

model Network
  Volume a(V = 0.01);
  Volume b(V = 0.02);
equation
  connect(a.port, b.port);
end Network;
```

该 `connect` 生成的方程等价于

```text
a.port.p = b.port.p
a.port.m_flow + b.port.m_flow = 0
```

验证：把两个容积的总质量相加并求导，应恒为零（无外流时）；交换两个容积的连接顺序，结果必须逐位一致。若总质量随时间漂移，优先检查 `m_flow` 是否确实声明为 `flow`。

另一个常用校核是“能量审计”：把网络各处的烩流与热流相加，净额应等于内部储能的变化率。若不等，通常说明某个接口丢了烩流，或符号约定与其它组件不一致。

为了系统化，建议在库里维护一个小型“连接测试网络”，把所有连接器组合都接一遍，每次改动后自动运行守恒校核，把连接器的语义错误挡在库的边界内，而不是流到下游模型里。

## 6. 常见坑与排查

- 漏写 `flow`：流量被当作势变量相等，质量不守恒；核对连接器声明。
- 符号约定混用：部分组件“流入为正”、部分“流出为正”，守恒式符号错乱。
- 用 `=` 代替 `connect`：手工传递数值只复制一侧，丢掉守恒方程，多端连接时尤其危险。
- stream 误用：比焓用普通变量导致反向流混合错误，出现不物理的温度跳变。
- 过约束：同一连接上重复固定势变量或流量，初始化或求解报奇异。
- 单位不一致：接口单位缺失或混用（表压/绝压、g/s 与 kg/s），守恒结果量级错。
- 多组分遗漏：只守恒总质量而不管组分，混气浓度不守恒。
- 方向依赖：组件反接后结果不同，说明连接器语义不完整。
- 表压与绝压混用：一侧按表压、一侧按绝压解释，网络平衡虽成立，数值却差一个大气压。
- 跨域混连：把不同物理域的同名变量误连到同一集合，生成量纲不一致的方程。

诊断顺序：连接器声明（势/flow/stream）→ 符号约定 → 连接集合方程 → stream 混合 → 单位 → 守恒校核。

## 7. 检查清单与参考

检查清单：
1. 每个连接器的势变量与流变量成对且带单位；
2. 全模型符号约定统一并成文；
3. 未用 `=` 手工传递应守恒的量；
4. 流体连接器使用 `stream` 描述比焓与组分；
5. 无重复固定同一物理量导致的过约束；
6. 组分与总质量都守恒；
7. 组件反接测试通过；
8. 每个算例校核了总质量与总能量收支。
