# Modelica 声明式方程、变量与模型平衡

## 1. 结论与适用场景

Modelica 的 `equation` 用于表达变量之间的物理关系，而不指定从左到右的计算顺序。编译器会先展开层次模型、生成连接方程、进行符号处理与方程排序，再选择状态变量并安排数值求解顺序。因此，模型的正确性取决于"关系是否成立"，而不是"语句的书写顺序"。

这一特性决定了 Modelica 特别适合需要组合与复用的多物理场系统：热流体网络、电气与机械耦合、控制回路，以及需要在不同层次复用同一个组件的场景。只要每个可独立使用的组件在接口约束计入后保持结构平衡，它就能够被连接成更大的系统而无需修改内部方程。

判断一个组件是否"可复用"的核心标准是结构平衡，而不是代码能编译通过。一个欠定的组件在单独测试时可能因为外部给定而勉强运行，一旦嵌入系统便立即暴露矛盾。因此，本节的适用场景包括：设计新组件库、把已有代码块改造成可连接组件、以及在拼接模型报出平衡错误时定位问题来源。

需要提醒的是，方程式的写法带有一种"全局责任"：局部一处多余或缺失的关系，会以难以预测的方式干扰整个系统的求解。养成"先孤立验证组件、再逐步组合"的习惯，能让平衡错误在被引入时就暴露，而不是等到大型模型成型后才去剖丝抽茧。

## 2. 原理与语言语义

先厘清变量的角色。`parameter` 在一次仿真中保持常量，`constant` 是更强的全局常量语义；普通 `Real` 既可能是代数量也可能是状态量，最终由模型结构与工具的状态选择共同决定；带 `der(x)` 的变量可能成为状态。`equation` 中的等号表达关系而非赋值，`algorithm` 中的 `:=` 才是按顺序执行的赋值。

连接器（`connector`）是语义的关键。连接器把变量分为势变量（potential，如温度、压力、电压）与流变量（flow，如热流、质量流量、电流），流变量用前缀 `flow` 声明。`connect(a, b)` 会自动生成两类方程：所有势变量相等，所有流变量之和为零。这意味着连接网络本身就在贡献方程，无法只统计源码中手写的等号数量来判断平衡。

事件与离散行为由 `when`、`if` 表达式以及离散变量承担，它们会在特定条件触发时改变方程的活动性。条件组件（`if` 表达式或条件声明的组件）在不同时间区间内可能激活不同的方程集合，因此平衡需要在每一种活动配置下分别成立。这类结构常成为"偶尔过定"的根源。

还需要强调状态选择的可观测性。工具在展开模型后会把系统归约为 DAE，并尽量选取数量最小且数值稳定的状态集合。两个物理上等价但写法不同的模型，可能得到不同的状态数和不同的初始化难度。当出现初始化失败或刚性问题时，除了检查方程本身，还应考虑是否存在可化简的冗余关系，或者是否需要用 `stateSelect` 给出提示，让工具倾向于把某个变量当作状态。

## 3. 关键公式与语法

结构平衡的判据可写为未知量与独立方程数量之差为零：

$$
N_{unknown} - N_{equation} = N_{freedom} = 0
$$

当 $N_{freedom} < 0$ 时模型过定，会产生冗余冲突；当 $N_{freedom} > 0$ 时模型欠定，缺少约束。计数必须针对展开后的系统，并把连接器与函数的影响计入。

对由 $N$ 个组件组成的连接网络，`connect` 自动生成

$$
\phi_1 = \phi_2 = \cdots = \phi_N, \qquad \sum_{i=1}^{N} f_i = 0
$$

即势变量处处相等、流变量代数和为零。这正是网络上守恒关系的来源，也是组件内部不应重复书写整网守恒的原因。

Modelica 模型的数学本质是微分代数方程系统：

$$
F(\dot{x}, x, y, t) = 0
$$

其中 $x$ 是状态变量，$y$ 是代数变量。初始化时需额外提供或推导初值关系，通常可写为

$$
G(x(t_0), \dot{x}(t_0), y(t_0)) = 0
$$

初值关系与状态导数的取值共同决定启动点，若与 `start` 属性互相冲突，工具会报出初始化失败。时间导数则由声明关系与微分方程共同确定：

$$
\frac{d x}{d t} = \dot{x}
$$

这些关系全部由方程隐式描述，不需要在源码中显式排序。

从计数角度看，连接器的每个实例会引入势变量与流变量两类未知量，而 `connect` 又会生成相当数量的方程，二者在结构上相互抵消。只有当你把连接器视为"接口约束"而非普通变量时，手算平衡才不至于漏项。实务中更稳妥的做法是依赖工具的结构分析报告，而不是手工数等号。

## 4. 工程做法与参数

推荐的建模顺序如下。第一，明确组件边界与存储量：每个组件存什么、通过哪些端口与外界交换什么。第二，定义端口与参数，势变量与流变量必须配对出现，参数应带 SI 单位与合理范围。第三，写守恒方程，描述存储量随时间的变化与流入流出。第四，写构成关系，把势差、流与物性联系起来。第五，加入必要的初始化约束，避免与 `start` 属性冲突。第六，用极限工况与解析解验证。第七，再与其他组件连接成系统。

参数设计上，为物理量声明正确的 SI 类型、`min`、`max`、`start` 与 `nominal`，能让工具在做结构检查之外还做单位检查，从而在仿真前就发现量纲错误。把可复用的部分标记为 `partial`，让不可独立实例化的组件显式暴露其接口需求，有助于把"不该单独使用"的组件排除在平衡检查的误报之外。

状态选择不需要手动指定，但你可以通过 `stateSelect` 属性给出偏好提示（如 `StateSelect.prefer`），帮助工具在多个候选状态中做出更稳定的选择。

测试策略上，建议为每个组件先做"单元级"检查：在不连接任何外部网络的情况下，给端口补上临时边界，确认它能独立求解并得到解析解。再做"集成级"检查：把多个组件连接后，验证守恒量与响应曲线。参数扫描可以从极限值开始，例如把热容或热阻取极大或极小，观察结果是否趋于解析极限；若极限行为不符合物理直觉，往往说明方程或符号写反了。此外，为组件准备一份带单位的参数默认值，能让单位检查在早期发现量纲不一致。

## 5. 可复现示例

下面给出一个热能存储组件与一个热端口连接器，以及两个组件的连接示例。示例展示守恒方程如何写成关系式，以及连接如何自动生成方程。

```modelica
connector HeatPort
  Modelica.Units.SI.Temperature T;
  flow Modelica.Units.SI.HeatFlowRate Q_flow;
end HeatPort;

model ThermalCapacitance
  parameter Modelica.Units.SI.HeatCapacity C = 1000;
  Modelica.Units.SI.Temperature T(start = 293.15);
  HeatPort port;
equation
  T = port.T;
  C * der(T) = port.Q_flow;
end ThermalCapacitance;

model FixedHeatFlow
  parameter Modelica.Units.SI.HeatFlowRate Q0 = 100;
  HeatPort port;
equation
  port.Q_flow = -Q0;
  port.T = 300;
end FixedHeatFlow;

model System
  ThermalCapacitance cap(C = 500);
  FixedHeatFlow src(Q0 = 50);
equation
  connect(src.port, cap.port);
end System;
```

在这个系统中，连接生成 `src.port.T = cap.port.T` 与 `src.port.Q_flow + cap.port.Q_flow = 0` 两条方程，与两个组件内部方程共同构成平衡系统。

```bash
# 以 OpenModelica 从命令行仿真并输出结果
omc -s modelica-build.mos
```

## 6. 常见坑与排查

第一类坑是把方程当赋值语句，依赖文本顺序书写，导致模型在重排后行为改变。判断方法是问"交换两行是否改变物理含义"，若答案是否定的，说明写法正确。

第二类坑是给状态同时固定初值和互相冲突的初始方程。若 `start` 与初始化方程给出不同值，初始化阶段会报不一致。应先明确哪些变量是强约束的初值。

第三类坑是在组件内部重复书写连接网络已经生成的守恒关系，造成过定。组件应只描述自己内部的存储与构成关系，跨组件的守恒交给连接器。

第四类坑是用大量输入输出信号替代物理端口，破坏了可组合性。信号不参与流守恒，无法自动生成网络级方程，会让平衡检查失效。

第五类坑是忽视条件组件带来的活动方程变化。含有 `if` 表达式或条件组件的模型，应在每一种配置下分别检查平衡，否则会在某些工况下突然报错。

第六类坑是混淆物理端口与信号接口。信号接口不会生成守恒方程，若把质量或能量的流动写成信号而不使用流变量，网络级守恒就不会被自动保证，模型看起来能跑，但总量不守恒。第七类坑是在连接器里混入不必要的状态。连接器应尽量保持纯接口性质，不携带存储或导数量，否则会在每个连接点引入额外动态，既降低效率又增加平衡分析的难度。

## 7. 检查清单与参考

建模前：明确边界与存储量；为端口区分势变量与流变量。

建模中：用关系而非赋值书写方程；避免在组件内重复整网守恒；为参数与变量声明 SI 单位及合理属性；用 `partial` 明确不可独立实例化的组件。

验证时：检查局部与全局平衡；用极限工况和解析解验证；对含条件组件的模型逐配置检查。

交付前还应确认：连接器的势变量与流变量成对且命名一致；每个可独立使用的组件在接口约束下平衡；参数默认值带单位且范围合理；组件不携带与职责无关的存储。
