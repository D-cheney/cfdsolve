# Modelica 单位、nominal 与数值缩放

## 1. 结论与适用场景

Modelica 变量可声明 `quantity`、`unit`、`displayUnit`、`min`、`max`、`start` 与 `nominal` 等属性。它们表面相似，职责却完全不同：`unit` 用于量纲一致性检查，`displayUnit` 只改变结果的显示方式，`nominal` 表示变量的典型非零量级并供求解器缩放残差与误差控制，`start` 通常是初始化猜值，`min` 与 `max` 主要用于检查、界面与优化约束。

区分"单位正确"与"数值缩放合理"是本主题的核心。单位正确保证方程在物理量纲上自洽，能拦截把温度当压力、把质量分数当体积分数这类错误；数值缩放则让求解器公平地处理量级差异巨大的方程，避免某些残差在统一绝对尺度下被忽略或过度放大。

典型适用场景包括多组分系统（压力约为 $10^5$ 量级，而质量分数约为 $10^{-3}$ 量级）、电力与电子系统（电压与电流量级悬殊）、以及热流与化学动力学耦合（时间尺度从毫秒到小时）。在这些模型里，不设置 `nominal` 往往导致步长过小、迭代缓慢，甚至初始化失败。反之，为所有变量随意设置统一的 `nominal` 反而会破坏缩放。

需要把这个问题当作两个独立的验收项：一是量纲是否一致，二是数值尺度是否被公平对待。前者可以在建模阶段由工具静态校验，后者只能在仿真与参数扫描中观察。很多"模型能跑但结果可疑"的问题，根源都在后者而前者完全正常。因此，读完本节后你应能区分两类错误，并分别用单位检查与缩放验证去定位。

换一个说法：单位回答"这个量是什么"，nominal 回答"它大概有多大"。前者是质的约束，后者是量的标定。两个问题需要分别验证，不能用其中一个的成功掩饰另一个的缺失。

## 2. 原理与语言语义

`unit` 属于类型系统的一部分。工具在编译期或结构分析阶段收集所有方程两侧的单位并进行量纲比对，不一致会给出警告或错误。这是"静态"检查，与具体数值无关，因此能在仿真前发现问题。

`displayUnit` 只在呈现层起作用。当你以摄氏温度或千米显示结果时，底层的物理量与方程完全没有改变。特别要注意温差：显示同一温度时，摄氏与开尔文的偏移是常数；而表达温差时，摄氏温差与开尔文温差在数值上等价，偏移应当消失。若工具或用户误把显示换算当成物理平移，会得到错误结果。

`nominal` 的语义是"这个变量的典型非零量级"。求解器在计算残差范数与误差估计时，会把每个方程按相关变量的 nominal 做缩放，从而让不同量级的方程在统一的相对尺度下比较。它既不是初值也不是边界条件，而是一个量级标定。`start` 与 `min/max` 则分别服务于初始化与约束检查，二者都不应被当作自动生效的物理限制。

从工具实现角度看，结构分析阶段会先用 `unit` 做量纲校验，再在数值求解阶段用 `nominal` 构造缩放矩阵。这两个阶段相互独立：修正单位不会改变缩放因子，反之亦然。`quantity` 主要提供语义描述与图形界面提示，不参与刚性检查；但它能让模型更易读，并帮助工具在单位缺失时推断意图。理解这些属性的分层职责，可以避免把展示需求与求解需求混为一谈。

## 3. 关键公式与语法

量纲一致性的核心是方程两侧单位相同。例如压力的单位可表示为

$$
\mathrm{unit}(p) = \mathrm{kg} \cdot \mathrm{m}^{-1} \cdot \mathrm{s}^{-2}
$$

任何把压力与能量相加的方程都会因此被标记。显示单位的换算是仿射（或线性）映射，以温度为例：

$$
T_{\text{degC}} = T_{\mathrm{K}} - 273.15
$$

而温差满足

$$
\Delta T_{\text{degC}} = \Delta T_{\mathrm{K}}
$$

这正是"温差不能用摄氏平移处理"的数学来源。

数值缩放方面，求解器对第 $i$ 个残差分量做如下归一化，其中 $n_i$ 由相关变量的 `nominal` 推导：

$$
\tilde{r}_i = \frac{r_i}{n_i}
$$

误差控制的代价函数可写为归一化残差的平方和：

$$
J = \sum_{i=1}^{N} \tilde{r}_i^{2}
$$

若某个 $n_i$ 设得过小，该残差会被过度放大，逼使求解器在此处减小步长；若设得过大，真正重要的方程在 $J$ 中的权重被压低，可能被忽略。缩放的本质是调整各方程在代价函数中的相对权重。

初始化的目标与之相彷。工具希望在启动时刻找到一组满足所有方程（包括初始方程）的初值，而各变量量级差异会直接影响该非线性方程组的条件数。合理的 `nominal` 能改善条件数，使初始化与后续积分都更稳定。相反，一个量级极小的变量若未标定，其相关方程几乎不参与残差，导致初值偏差被忽视。

## 4. 工程做法与参数

设置 `nominal` 的经验做法是：对每个远离 $1$ 的状态量与代数量，给出其工况下的典型量级，而不是边界值或极值。例如压力取 $10^5$、质量分数取 $10^{-3}$、组分浓度取痕量值。对符号会变化的通量与流量，应取典型绝对值量级。对量级近似为 $1$ 的变量，可省略或显式写 `nominal = 1`，但不要对全体变量一律写 $1$。

单位方面，优先使用 `Modelica.Units.SI` 中的类型，让 `quantity` 与 `unit` 成对出现。需要以工程单位展示时，用 `displayUnit` 而不是在方程里做换算；如果必须在模型内部使用非 SI 单位，应集中在一处转换，避免散落的魔数。

`start` 应给出接近真实初值的合理猜测，并用必要时的初始方程把强约束写清楚，不要依赖 `start` 去强制某个边界条件。`min` 与 `max` 用于表达物理可行范围，配合断言可在越界时报警；但不要期望它们会在积分过程中自动把变量截断。验证时，应比较缩放前后初始化的残差、步长与事件定位是否改善。

工程上建议把量级信息集中记录：在组件说明中标注关键变量的典型取值范围，便于后续维护者判断 `nominal` 是否合理。当模型被重用到不同工况时，应重新审视 nominal——原本在高压下合适的取值，在低压工况下可能不再适用。可以把 nominal 写成由参数推导的表达式，使其随工况自适应，而非硬编码常数。

## 5. 可复现示例

下面给出一个同时包含单位、显示单位、初值与 `nominal` 的模型，展示这些属性的正确用法。

```modelica
model ScaledTank
  // 压力用 SI 单位，但以 bar 显示；nominal 标定典型量级
  Modelica.Units.SI.Pressure p(start = 101325, nominal = 1e5)
    "Tank pressure";

  // 质量分数量级很小，必须设置 nominal 才能被求解器公平对待
  Modelica.Units.SI.MassFraction wEthanol(start = 0.01, nominal = 1e-3);

  // 温度与温差：显示用摄氏度，但物理量始终是开尔文
  Modelica.Units.SI.Temperature T(start = 293.15, displayUnit = "degC");
  Modelica.Units.SI.TemperatureDifference dT(nominal = 10);

  parameter Modelica.Units.SI.Volume V = 0.05;
  parameter Modelica.Units.SI.Mass m = 50;
equation
  // 理想气体关系，两侧量纲必须一致
  p * V = m * 287.05 * T;
  T = 293.15 + dT;
  wEthanol = 0.01;
end ScaledTank;
```

## 6. 常见坑与排查

第一类坑是把全体变量的 `nominal` 统一设为 $1$。这等于放弃缩放，跨数量级模型会出现残差不平衡，表现为某些方程几乎不被修正。

第二类坑是把 `displayUnit="degC"` 用于温差并期望自动平移。物理量本身是开尔文，温差换算不应引入常数偏移。

第三类坑是把 `start` 当作边界条件。`start` 只是初始化猜值；真正的边界要靠方程或固定的初值关系表达，否则模型可能在初值处满足却在后续发散。

第四类坑是期望 `min` 与 `max` 在积分中自动截断变量。它们主要用于检查与约束，不保证过程量的硬限制。

第五类坑是关闭单位检查或混用单位制，让量纲错误直到运行期才以数值异常的形式出现。应开启编译期单位检查并处理全部提示。

第六类坑是对符号变化的流量设置了错误的 nominal 符号。`nominal` 应取量级而非带符号的当前值。

第七类坑是忽视属性之间的相互作用。`min` 与 `nominal` 同时存在时，若 `min` 设得比典型量级还大，会让检查与缩放相互矛盾；`start` 与初始方程也可能因数量级不同而牍突。应把它们放在同一张表里核对，而不是逐项单独设置。第八类坑是过度缩放：为过度修正某个残差而人为调小 nominal，会牺牲其他方程的精度，应回到物理量级而非用调参来掩盖问题。

## 7. 检查清单与参考

设置时：为公共连接器与参数声明 SI 单位；为远离 $1$ 的状态量与代数量设置典型 nominal；用 `displayUnit` 处理展示需求而非修改物理量。

验证时：启用并处理全部单位检查提示；比较缩放前后的初始化残差、步长与事件定位；导出结果时同时保留原始单位与显示单位。

交付前还应确认：温差与温度的区别已正确处理；`start` 与初始方程不冲突；`min/max` 的语义未被误用为积分限幅；模型内部没有散落的单位换算魔数。
