# Modelica 实验设置、求解器、容差与结果采样

模型翻译后可能是 ODE、DAE 或混合系统。求解器选择应基于刚性、事件、精度和成本，而不是固定沿用工具默认值；默认设置只对"平均情况"友好，遇到多尺度或强事件系统往往既慢又不准。

## 1. 结论与适用场景

若模型含显式快速动态、需要长时间积分，或事件频繁，应改用支持事件定位的隐式 BDF 类求解器（DASSL、IDA 等），而不是显式方法。判据是最小时间常数与仿真跨度之比：当二者相差三个量级以上时，刚性几乎必然出现，显式方法的稳定步长会被最快模态压得极小。反过来，状态数不大、无刚性、要求高精度短时积分时，显式方法反而更快。工程上应始终比较至少两档容差，必要时比较两类求解器，并用物理输出（峰值、事件时刻、积分量）而非步数判断是否收敛，因为"能跑完"不等于"算对了"。此外还要区分纯 ODE、index-1 DAE 与混合系统，它们的初始化与事件处理难度依次递增。混合系统要求求解器在事件时刻暂停、更新离散状态并重启积分；若事件设计不当形成刷屏式刷新，会同时拖慢仿真并污染结果。

## 2. 物理/数学基础

Modelica 工具把模型展开成带代数约束的微分代数方程组（DAE）：

$$F(t,x,\dot x,y)=0,\qquad 0=g(t,x,y)$$

其中 $x$ 为微分状态、$y$ 为代数量。工具先做指标约简与符号处理，最终交给求解器的可能是显式 ODE 或 index-1 DAE。隐式 BDF 类方法在时间步上用向后差分逼近导数

$$\sum_{j=0}^{k}\alpha_j\,x_{n+j}=h\,\dot x_{n+k}$$

每个时间步解一个非线性方程组，常以修正牛顿迭代推进

$$J(x)\,\Delta x=-F(x)$$

刚性来自特征值跨度

$$S=\frac{|\lambda_{\max}|}{|\lambda_{\min}|}\gg 1$$

此时 BDF 能在大得多的步长下保持稳定，代价是每步需要 Jacobian 与线性求解；显式方法则被迫用最快模态决定步长，效率极低。变阶变步长策略会根据误差估计在低阶到五阶之间切换。工具在首次积分前还需完成一致初始化，即求出同时满足全部代数约束与初始方程的 $x$ 与导数；初始化失败通常源于缩放、起点或约束冲突，而不是求解器本身。

## 3. 关键模型与公式

变步长求解器用误差范数控制步长，要求每个分量的局部误差满足

$$\left|\frac{\hat x_i-x_i}{\mathrm{rtol}_i\,|x_i|+\mathrm{atol}_i}\right|\leq 1$$

相对容差按变量尺度控制误差，绝对容差在变量接近零时兜底。当物理量本身很小（如 $10^{-6}$ 量级）时，仅靠默认绝对容差会失真，应显式给出 `nominal` 或收紧 `atol`。事件由连续表达式过零触发，求解器必须定位零点、重启并重新初始化，事件密度越高成本越高。稠密输出用于在内部步之间插值出规则采样点，它只影响结果文件，不改变积分精度。步长控制本身是一个反馈回路：求解器根据上一步误差估计预测新步长，并设置上下限以避免步长抖动。

## 4. 工程做法与参数

常见默认容差为 $10^{-6}$ 量级，但应按物理量级调整：电压、温度、流量各有合适尺度。内部步长由误差控制决定，结果文件间隔通常只是采样或插值间隔；把输出点设得很密不会自动提高积分精度，却会增大文件，而设得太稀会错过峰值与事件后瞬态。若关心高频控制或快速瞬态，应限制最大步长。不同工具的算法名并不统一（DASSL、ida、CVODE 等），迁移模型时不能照搬字符串。选择求解器前先修正不必要的事件、缩放与初始化，再横向比较；完整的工具版本、算法、容差、输出间隔与参数集必须随结果一起保存。结果文件只应保存真正需要的变量，输出变量越多、采样越密，文件越大且后处理越慢。

## 5. 可复现示例

下面给出一个含快慢两个时间常数的刚性网络，并直接抄用其实验设置。

```modelica
model StiffRC "刚性双时间尺度 RC 网络"
  parameter Real R1=1.0, C1=1e-6 "快模态";
  parameter Real R2=1e3, C2=1e-3 "慢模态";
  Real v1(start=1, fixed=true);
  Real v2(start=0, fixed=true);
  Real u = 1;
equation
  R1*C1*der(v1) = u - v1 - (v1 - v2);
  R2*C2*der(v2) = (v1 - v2);
  annotation(experiment(
    StartTime=0, StopTime=1, Tolerance=1e-7,
    Algorithm="Dassl", Interval=0.01));
end StiffRC;
```

实验步骤：(1) 用默认容差运行，记录 $v_2$ 峰值与积分步数；(2) 把 `Tolerance` 收紧到 $10^{-8}$ 再运行，比较差异；(3) 换成显式方法，观察步数是否失控；(4) 改用另一种隐式求解器，比较轨迹一致性；(5) 保存设置文件作为回归基线。

## 6. 常见坑与排查

- 混淆采样与步长：以为 `Interval` 越小越准，其实精度由容差决定。
- 容差过松：关键瞬态被抹平，事件时刻偏移。
- 容差过紧：步数剧增却无精度收益，应先查缩放。
- 忽略缩放：量级差异导致误差被某些变量主导，应收紧或设 `nominal`。
- 事件爆炸：不连续函数隐式产生大量事件，应改用合适函数或降噪。
- 单位不一致：参数单位与方程不一致，容差失去物理含义。
- 初始化失败：把约束冲突误判为求解器问题，应先检查起点与缩放。
- 步长失控：未设最大步长，快速瞬态被跳过。
- 未记录设置：只保存曲线，无法复现。

## 7. 检查清单与参考

1. 是否比较至少两档容差并确认关键输出收敛；
2. 内部步长与结果采样是否区分清楚；
3. 刚性是否通过求解器对比得到确认；
4. 事件时刻、峰值与积分量是否被正确解析；
5. 工具版本、算法、容差、输出间隔与参数集是否已记录。
