# 吉隆口岸场景：三维无网格仿真模板

> 最新 20 倍加密及“只将云图生成视频”的工作流见 [CLOUD_480K_TEMPLATE.md](CLOUD_480K_TEMPLATE.md)。本文件保留基础三维方法说明。

本文件是新三维路线的主入口。旧版 `simulate_sph.py` 和横向复制的 2.5D 结果保留为历史资料，不能作为新三维计算的验证数据。三维结果按运行名称存入 D 盘，实际完成时长以每次运行的 `summary.json` 为准；配置的 90 分钟不是完成证明。

## 1. 物理与数值模型

每个粒子独立携带 `(x,y,z)`、`(vx,vy,vz)`、质量、核估计密度和压力。邻居搜索在三维空间中完成，不用谷地中心线约束运动，也不复制展示子粒子。默认 80×30×10＝24000 粒子，5 m 初始间距，每粒子代表 125 m³，参考密度 1850 kg/m³，总参考体积 300 万 m³，总质量 55.5 亿 kg。

- 三维弱可压缩 SPH，Wendland C2 核，核长 h＝1.3Δp，支持半径 2h。
- 密度为三维核求和 `rho_i = Σ m_j W_ij`。自由表面核截断会导致低密度估计，不能据此直接解释含沙浓度。
- 压力使用正压线性状态方程 `p_i = c0² max(rho_i-rho0,0)`；相互作用分母取不低于 rho0 的密度。声速默认 150 m/s，必须结合最大马赫数、密度偏差判断弱可压缩近似是否足够。
- 三维对称压力梯度、Monaghan 型人工黏性、正则化宾汉等效黏性；等效运动黏度 `nu_eff = min(nu_max, nu0 + tau_y/(rho0 sqrt(gamma_dot²+epsilon²)))`。默认屈服应力 200 Pa、基础运动黏度 0.5 m²/s、剪切率正则化 0.02 s⁻¹、黏度上限 20 m²/s，均为未标定假设。
- 重力直接作用于 z 方向。地面使用现有 DEM 双线性插值及其梯度，通过单边接触、零回弹和库仑切向冲量近似处理。接触不是完整的 SPH 固体边界粒子方法；缺失边界核补偿和接触投影会影响近床压力、能量及薄层流动。
- 时间步同时满足声学 CFL、加速度及黏性限制，并截断至下一输出时刻。全程保持固定粒子质量。
- DEM 外框使用反射限位并记录碰撞次数；若粒子碰到外框，需扩大域或建立可验证的开放边界。

GPU 空间哈希仅用于找邻居，不是欧拉动力网格。哈希碰撞通过真实三维单元坐标过滤；桶溢出或邻居表超过 256 项会使计算报错，不能静默忽略粒子。邻居表采用额外 0.5Δp 的缓冲区；任何粒子相对上次建表位置移动达到缓冲宽度的一半时，在下一次求力前重建。每次作用仍用真实 2h 支持半径筛选。

## 2. 山体和源区构建

复用 `data/processed/terrain_model.npz` 中完整高程面、局部东/北坐标。求解器直接采样 DEM 高程，**不使用旧版经过强制下坡处理的 path_z**。旧路径只给出源区的位置与初始化朝向。

默认源区在路径起点下游方向布置 400 m × 150 m × 50 m 的体积粒子阵列，各柱底面跟随原始 DEM。它是一次性释放的假设物质块，不是经测量重建的冰湖库容或实际水位面。粒子可自由横向运动、纵向运动和垂向运动；原始地形若形成盆地，模型可能滞留，不能强行指定到达口岸。

现有 DEM 标称约 30 m。5 m 粒子间距提高了流体离散密度，不会产生 5 m 精度的真实地形；桥梁、房屋、狭窄沟槽尚未解析。更换地形时先确认水平坐标为米、垂向基准一致，再检查源区粒子全在有效 DEM 范围且不穿地。

## 3. 环境和运行

当前实现使用 Python 3.11、NumPy、SciPy、Taichi 1.7.4、Matplotlib、imageio-ffmpeg。主科学计算环境沿用本机 Python；Taichi 独立放在 `D:/openclaw/codextemp/sph3d-libs`。脚本用附加搜索路径加载它，不覆盖原环境 NumPy。默认 `CUDA_VISIBLE_DEVICES=1` 对应本机 RTX 4060，换机器必须核对 GPU 编号。

实际环境版本已锁定在 `config/requirements-sph3d.txt`。设备顺序固定为 `CUDA_DEVICE_ORDER=PCI_BUS_ID`，然后选择编号 1；否则默认 CUDA 顺序可能与 nvidia-smi 不一致。程序会检查 CUDA 是否成功启用，避免静默退回 CPU。

在项目目录运行：

```powershell
$env:TEMP = 'D:\openclaw\codextemp'
$env:TMP = 'D:\openclaw\codextemp'
python -m pip install --no-deps --target D:\openclaw\codextemp\sph3d-libs taichi==1.7.4
python src/verify_sph3d.py
python src/simulate_sph3d.py --duration 60 --tag pilot_60s
python src/simulate_sph3d.py --tag baseline_90min
python src/render_sph3d.py --tag baseline_90min
```

也可以在长时程运行期间另开终端，等待计算完成后自动核查、输出报告与四个视角视频：

```powershell
python src/finalize_sph3d.py --tag baseline_90min --wait
```

普通软件包下载较慢时，本机提供 `src/install_sph3d_runtime.py`，对固定版本进行分段下载并核对 PyPI 发布的 SHA256。该安装辅助程序需要联网；实际求解和视频生成不需要联网。

中断后续算：

```powershell
python src/simulate_sph3d.py --tag baseline_90min --resume
```

续算使用上一个已保存时间点的位置和速度，重建密度、压力和邻居表。不要更改粒子数、地形或材料参数后复用同一检查点。更改参数时使用新的 `--tag`，避免混淆结果。

`config/sph3d.json` 是新求解器唯一配置入口；旧 `model_config.json` 的一维摩阻、六倍增重和人工沉积带不参与新求解器。数据默认写入 `D:/openclaw/codextemp/jilong_sph3d/<tag>/`。虽然路径名称含 temp，此目录包含成果，不能作为可随意清理的临时文件。

## 4. 输出与核查

- `frame_XXXX.npz`：保存真实三维位置、速度、核估计密度、压力、等效黏度及物理时间；前 120 s 每 2 s 保存，之后每 30 s 保存。
- `checkpoint.npz`：最近完整保存状态。
- `diagnostics.json`：每帧速度、动能、质量、参考体积、密度偏差、马赫数、接触比例、外框碰撞次数和实际计算耗时。
- `config_used.json`：实际使用的配置。
- `summary.json`：正常完成后才生成，含实际物理时长和计算摘要。
- `quality_check.json` / `RESULTS_3D.md`：全部时间帧核查和实际运行结论；由 finalize 脚本生成。
- `final_particles_3d.vtk`：最终粒子位置、速度向量和速度大小，可直接在 ParaView 打开。
- `videos/01_volume.mp4`：三维体积粒子与 DEM。
- `videos/02_plan.mp4`：真实三维状态的俯视投影。
- `videos/03_side.mp4`：真实三维状态的北向—高程投影。
- `videos/04_diagnostics.mp4`：速度、密度偏差与动能变化。

视频使用全部保存帧，显示实际物理时间，局部镜头自动涵盖粒子分布区域。没有计算的时间段不补造传播画面。

先通过小规模独立检查：核求和与 NumPy 全对全计算对照、粒子内力总和、三维自由飞行、平床非穿透，以及运动后重用邻居表的核求和对照。再检查场地试算的有限值、哈希溢出、质量、密度压缩及外框碰撞。以上通过只能说明实现与基本数值行为，不代表泥石流工程验证完成。

正式研究还需：静水压力、溃坝、斜槽流与已知宾汉流测试；改变时间步和粒子间距检查收敛；实测流痕/到达时间/堆积范围标定；使用边界粒子或更成熟边界算法验证 DEM 接触误差。减半三维间距时体积粒子数约增加八倍，声学时间步也约减半。

## 5. 当前物理范围和后续扩展

本版是固定山体上的三维单一混合物非牛顿 SPH 原型。尚未求解冰川传热融化、实际冰湖水位变化、固液分相、孔压、岩土破坏、床沙侵蚀裹挟、可变床面和建筑物破坏。总质量不按里程人为增长。若要模拟“融化—湖水积累—溃决—裹挟成泥石流”的完整链条，需要逐一增加这些过程、对应输入数据与验证算例。
