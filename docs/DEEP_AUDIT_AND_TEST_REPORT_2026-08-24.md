| 范围 | 原缺陷及风险 | 整改结果 | 回归证据 |
|---|---|---|---|
| 路由 | 使用前缀匹配和默认回退，任意无效 URL 仍返回 200，并可能打开首篇文章或首个项目 | 改为显式路由和资源存在性判断；无效顶层、仿真、知识、论坛、Modelica 路径均返回 404 | 生产 HTTP 冒烟测试均返回预期状态 |

| 离线状态 | 数据库恢复后直接覆盖浏览器离线修改；存储禁用或配额异常会中断初始化/同步 | 对任务、项目、收藏、通知执行合并；本地存储异常被隔离；按脏数据分区同步 | Store 逻辑检查、数据库语义测试和浏览器刷新回归通过 |

## 7. 已知边界与后续方向

1. 当前部署是单机、本地回环地址模式。若开放局域网或公网，必须接入真实登录会话、服务端用户隔离、CSRF、防暴力破解、TLS 和反向代理；不能仅修改监听地址后直接暴露。
2. Modelica 模块是明确标识的 “CFD菜鸟 Modelica Lite”，不是完整 OpenModelica 编译器。任意 Modelica 类库、事件系统、DAE 指数约简、FMU 和外部函数需要后续接入受隔离的 `omc` 服务。
3. 元件算法当前保存为设计草稿，不执行任意脚本；这是本地安全边界，不应在 UI 中宣传为可执行算法。
4. 方腔模块是教学级涡量—流函数求解器，不等同于工业 SIMPLE、RANS/LES 或复杂网格 CFD；关键工程结论仍需独立网格验证和专业软件复核。
5. 社区发帖、点赞、举报和回复目前用于本地产品交互演示；多用户持久化、审核流和通知投递需要独立后端权限模型。
6. 本地离线合并解决当前单用户数据库短暂不可用场景，但不等同于多设备协同编辑或通用冲突解决系统。

这些限制已经在产品文案或文档中显式标注，避免将教学/本地能力误解为工业生产能力。
