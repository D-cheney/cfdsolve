# 布局系统与响应式规范

## 1. 设计目标

流研工坊同时包含内容阅读、工具列表、参数表单、计算结果和 Modelica 工程工作台。布局不能只依靠“桌面三栏、手机横向滚动”，而要根据任务类型选择结构：

- 内容发现页采用可伸缩 Feed/Grid；
- 文章与结果页采用主内容 + 支持信息；
- 仿真工具采用参数支持栏 + 主工作区；
- Modelica 采用宽屏三栏、中屏双栏加下沉属性区、手机纵向分区；
- 页面标题、导航、卡片正文统一在同一组垂直关键线上。

参考原则来自 [Material Design 3 canonical layouts](https://m3.material.io/foundations/layout/canonical-examples/overview)、[Fluent 2 Layout](https://fluent2.microsoft.design/layout) 和 [Carbon 2x Grid](https://carbondesignsystem.com/elements/2x-grid/overview/)。实现没有直接复制其视觉风格，只采用了可验证的栅格、间距和自适应方法。

## 2. 全局栅格

| 项目 | 规则 |
|---|---|
| 最大内容宽度 | 1360px |
| 页面边距 | `clamp(16px, 3.35vw, 48px)` |
| 基础间距 | 8px，允许 4px 半级 |
| 常规区块间距 | 桌面 72px、平板 50px、手机 42px |
| 面板圆角 | 10px |
| 触摸按钮 | 主要操作最小高度 40px，移动端保持清晰点击区域 |

导航、正文容器和页脚使用同一 `--layout-max` 与 `--layout-gutter`，避免导航品牌、标题和卡片边缘各自使用不同的起始线。

## 3. 响应式分段

### 1181px 及以上：Expanded

- Modelica 使用 216px 元件栏、流体主工作区、300px 属性栏；
- 仿真工具使用 320–360px 参数栏和自适应主内容；
- 首页能力卡片使用四列；
- 支持信息持续可见，减少反复切换。

### 821–1180px：Medium / Small desktop

- Modelica 主区域使用“元件栏 + 编辑器”；
- 属性与实验流程作为 supporting pane 下沉到主区域下方；
- 文章目录、非关键侧栏按需要隐藏；
- 列表卡片一般使用两列。

### 561–820px：Tablet / Large mobile

- 页面主结构改为单栏；
- 参数栏位于计算说明之前；
- Modelica 元件库成为横向可滚动工具带；
- 画布仅在自身区域内横向滚动，页面本身不得产生横向溢出；
- 属性区使用双列信息区。

### 560px 及以下：Compact mobile

- 所有主要内容按自然阅读顺序纵向排列；
- Modelica 属性区改为单列；
- 首页流场主视觉在手机端缩为 220px 高度，保留展示；
- 主操作按钮满宽或等分排列；
- 卡片取消不必要的固定高度。

## 4. 页面模式

### 首页

首屏承担价值说明、两个主行动和可信提示。桌面显示流场示意，手机将示意紧接在说明之后并缩小高度，保留其内容。后续能力卡片使用统一高度和底部行动位置，但手机端由内容决定高度。

### 无网格专题与全站背景（2026-09-10）

`FluidBackground.vue` 恢复自既有开发分支的 `ad2cada`，保留暖色流带、网格漂移、常驻流线、粒子、鼠标流光、光晕和扩散涟漪。组件挂载在路由树外，切换页面不会重复创建 Canvas。背景层为固定定位、不可接收指针事件；内容在上层，页面外壳透明，卡片使用半透明底色。科学图片、视频、编辑器等阅读面保留清晰底色，不以叠加动画改变数据颜色。

背景在默认设置下持续运行，手机端保留全部效果类型；系统设置为“减少动态效果”时停用动态效果，运行期间切换该设置也会立即响应。浏览器标签不可见时暂停，重新可见后恢复。保留原实现的设备像素比上限和手机流线数量控制。

无网格专题使用独立 `.meshfree-hero-grid`，避免继承首页 560px 最小高度。正文共享全站容器对齐线，卡片操作向底部对齐，视频在宽屏双列、手机单列显示；新增学习路径、模型范围、计算回放和资料下载的分区导航，锚点滚动预留两层导航高度。

样式分别位于 `assets/css/fluid-surfaces.css` 和 `assets/css/meshfree.css`，后者为专题组件的 scoped 样式。浏览器回归可用 `python tests/layout-background.browser.py --url http://127.0.0.1:4317` 执行，需要本机 Python Playwright 和 Edge；截图及检查报告写入忽略目录 `.run/layout-background/`。

本轮生产构建与类型检查通过。四档浏览器验收确认 Canvas 覆盖视口、8 个 CSS 动画持续运行、无鼠标操作时画布帧仍变化、指针可激发流场、锚点未被导航遮挡、路由切换没有重复 Canvas，以及动态偏好实时停用/恢复；页面未出现脚本错误。原有 9 篇文章、52 个资料文件与八个播放器继续通过集成检查。

### 仿真工具

参数栏是 supporting pane：桌面保持在视口内，移动端恢复正常文档流。说明区、方程和模型假设共享主内容对齐线。计算进行中覆盖主工作区，不覆盖参数输入。

### Modelica 工作台

宽屏保留工程软件熟悉的“资源—编辑—属性”模型。中屏不压缩画布，而把属性区放到下一行。手机端按以下顺序排列：

1. 项目与保存/检查/运行操作；
2. 横向元件工具带；
3. 画布/源码；
4. 问题与运行历史；
5. 元件属性、算法草稿、连线和实验流程。

画布宽度独立于手机视口，使元件拓扑仍保持空间关系；横向滚动被限制在画布容器内。

### 内容与社区

内容列表按 Feed/Grid 缩减列数；文章详情保留舒适行长；社区主题在小屏隐藏次要统计，但保留状态、标题和主要行动。

## 5. 验收要求

每次涉及布局的修改至少检查以下尺寸：

- 1440×900：桌面三栏、导航与内容关键线；
- 1024×768：中屏 supporting pane；
- 768×1024：平板单栏重排；
- 390×844：手机触摸目标、自然阅读顺序与横向溢出。

所有尺寸都需要满足：

- `document.documentElement.scrollWidth <= window.innerWidth`，明确设计为内部滚动的画布/表格除外；
- 标题不逐字换行；
- 主操作在首个可视区域内可发现；
- 固定/粘性区域不遮挡输入和标签；
- 页面隐藏某个模块时同时移除其高度占位；
- 键盘焦点轮廓不被容器裁剪。
