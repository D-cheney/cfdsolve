# CFD菜鸟 · 知识库框架与重建方案 v2

> 目标：把“空洞的条目堆”变成真正可用的工程知识库。
> 状态：340 篇按主题合并的深度文章已落地；原 382 篇扩展稿完成空壳重写后，于 2026-09-21 按同分类、同主题前缀合并为 222 篇完整专题。

## 1. 知识库是怎么工作的（现状逻辑）

- **唯一内容源**：`templates/knowledge/**/*.md`，每篇是「YAML Front Matter + Markdown」，标记 `template_version: flowlab-knowledge/1.0`。
- **导入器**：`server/services/knowledge-importer.ts` → 服务端用 **KaTeX 严格解析公式**（任一公式失败整篇拒收）→ 单个事务 upsert 进 SQLite（`content_items` / `categories` / `tags`）。
- **接口**：`/api/knowledge`（列表/搜索）、`/api/knowledge/:slug`（正文）、`/api/knowledge/categories`（分类计数）。
- **前台**：`/knowledge`，按 5 个**集合**浏览：CFD 理论 / OpenFOAM / Modelica / CAE 算法 / 无网格法；集合由分类 slug 前缀映射（`server/utils/knowledge-collections.ts`）。

## 2. 重建前诊断（历史问题）

1. **线上其实只有 44 篇**：cfd 40 + modelica 4。
2. **三个集合完全是空的**：OpenFOAM = 0、CAE 算法 = 0、无网格法 = 0。
3. **全量同步在本机跑不完**：`templates/knowledge` 共 **11,025 篇**，实测解析阶段直接 **OOM**（本机内存 1.67G）→ 知识库从未被完整导入，只剩早期的一小批。
4. **11,025 篇里 10,907 篇是机器生成的"逐文件源码桩"**（如"OpenFOAM 14 源码解析：options"，正文多为"未识别到明确的类/函数…"），本身没有知识价值。
5. **成篇内容偏短**：现有文章正文 ~600–1000 字符，缺公式推导、可复现算例、检查清单。

**结论**：不是"再塞点内容"，而是**先定义框架，再按框架重写存量 + 补齐空集合**，同时**把 1 万多条源码桩从"知识库"里剥离**。

## 3. 重建框架（集合 → 分类 → 文章）

### 集合 A · CFD 理论（cfd）
分类：流体力学基础 / 控制方程与物理建模 / 无量纲与尺度分析 / 数值离散方法 / 网格与离散质量 / 边界条件与初始化 / 湍流与近壁建模 / 传热与可压缩流 / 多相流与组分输运 / 数值稳定性与线性求解 / 验证确认与后处理
### 集合 B · OpenFOAM（openfoam）
分类：入门与算例组织 / 网格与几何 / 物理模型设置 / 数值格式与边界 / 运行与自动化 / 后处理与排错
### 集合 C · Modelica（modelica）
分类：语言基础 / 组件与复用 / 动力学与事件 / 物理域建模 / 仿真质量与初始化 / 与 CFD 联合仿真
### 集合 D · CAE 算法（cae）
分类：结构有限元 / 线性与非线性求解器 / 时间积分与特征值 / 物理离散（电磁/声学/粒子）/ 多物理耦合 / 优化·不确定度·降阶 / 算法全景图
### 集合 E · 无网格法（meshfree）
分类：方法选型 / SPH 理论与离散 / 核函数与邻域 / 边界处理 / 验证与基准

**当前规模**：340 篇深度文章，集合分布为 CFD 理论 99、OpenFOAM 82、Modelica 60、CAE 算法 64、无网格法 35。数量下降来自同主题内容合并，不是正文删减。

## 4. 每篇文章质量规范

- **深度**：正文不少于 2,400 字符；合并专题按内容完整性组织，不设机械字数上限；≥2 个**主题专属**公式（常数、量纲必须与主题对应）；≥1 个可执行的代码/配置/命令块（Python / OpenFOAM 字典 / Modelica 片段 / shell）。
- **数值证据**：≥6 处带单位的真实数值，并完成至少一次可核对的手算（重写前该指标为 0，是区分"真算过"与"套模板"的关键）。
- **结构按用途变化**：理论文章强调假设、方程和模型层级；工程文章强调参数取值、实施顺序与单因素对照；诊断文章强调症状、根因与判定试验。章节不要求采用同一顺序或同一标题，禁止跨主题复用同一套小标题。
- **共同证据要求**：必须包含定量判据、可复现示例、`现象 | 根因 | 判定试验` 失败模式表、独立对照与 ≥4 条真实参考文献（含年份，不得编造）。
- **禁止套话**：脚本套模板时期的高频空话（如"只改变这一类因素""另一位使用者应能在不询问原作者的情况下重建基线"）被列入黑名单，出现即校验失败。
- **Front matter**：`flowlab-knowledge/1.0` + 必填字段 + `tags`/`seo`；`level` 用 入门/进阶/工程/专题 分层。
- **公式**：行内 `$...$`、独立 `$$...$$`，只用标准 LaTeX（KaTeX 严格模式，禁私有字符）。代码块内的 `$` 不参与公式扫描，`cases` 环境里的 `\\[6pt]` 行距参数不会被误判为 `\[` 定界符。

## 5. 空的分类/集合怎么补

- 先在**集合 A** 内新增空分类：`控制方程与物理建模`、`无量纲与尺度分析`、`数值稳定性与线性求解`（DB 里已存在的空分类 `control-equations / dimensionless / numerical-stability / turbulence` 归并进去）。
- 集合 B / D / E 目前为空 → 按第 3 节框架**从零建全**（OpenFOAM 工程向、CAE 算法、无网格法）。

## 6. 10,907 条“逐文件源码库”的处置

- 不进入主知识库，避免把深度知识稀释成代码目录。
- 原始卡片继续保留在 `templates/knowledge/openfoam-source-files-v14` 作为离线源码索引；主知识库仅保留架构、离散、求解器和扩展流程等深度文章。

## 7. 已完成的实施结果

1. 原有 118 篇规范 Markdown 文章保留并梳理，补齐 3 篇仅存在于旧数据库的内容源。
2. 原先新增的 382 篇扩展稿已按主题整理：同一分类中名称前缀相同的“原理 / 工程设置 / 诊断验证”合并为一篇，`templates/knowledge/expanded/` 现有 222 篇，总深度内容源为 340 篇。
3. 新增内容采用独立目录分批导入，避免解析 10,907 条源码卡导致内存溢出。
4. SQLite 快照和本地运行库均同步到 340 篇，并完成 `PRAGMA integrity_check`。
5. **2026-09-20 空壳审计与全量重写**：首版 382 篇由脚本 `generate-expanded-knowledge.mjs` 套模板批量生成，虽通过当时的形式化校验，内容却是空壳——382 篇中 0 篇含代码块、0 篇含带单位数值，32 组公式覆盖全部文章，737 种句子跨文章重复（最高单句重复 158 次）。已删除该生成脚本，382 篇逐篇重写为含真实方程、真实常数/参数、可核对手算、工具配置片段与真实文献的技术文章。
6. **2026-09-21 同主题合并**：识别出 127 组同分类、同名称前缀的拆分稿，涉及 287 篇文章；合并后移除 160 个重复入口，正文内容完整保留在 127 篇综合专题中。合并脚本同时校验修改路径只能位于 `templates/knowledge/expanded/`。

## 8. 自动验收

运行 `npm run test:knowledge-expansion` 会逐篇检查**实质指标**，而不是字数与关键词：

- 文章总数（340）与五类分布（99/82/60/64/35）、slug/标题/摘要/正文唯一性；同一分类中不允许再出现相同主题前缀；
- 每篇 ≥2,400 字符、≥5 个二级标题、≥2 个独立公式、≥6 处带单位数值、≥1 个代码块、≥1 张 Markdown 表、`现象 | 根因 | 判定试验` 失败模式表、≥4 条带年份的真实参考文献；
- 套话黑名单与通用小标题黑名单零命中；无占位内容与乱码；KaTeX 与 MathML 正常生成；
- 全库层面：222 篇扩展专题具有 222 种完整标题结构签名，无被 4 篇以上共用的公式块，无被 3 篇以上共用的长段落，无被 4 篇以上共用的长句。

运行 `npm run knowledge:validate -- templates/knowledge/expanded` 会对全部新增文件执行导入器级校验（Front Matter、KaTeX 严格解析、公式定界符平衡）。
