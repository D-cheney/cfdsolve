**CFD菜鸟｜二维建模完整开发规格与验收书**

版本：1.0　编制日期：2026-09-21　适用项目：cfdsolve

文档性质：可执行的开发与验收规格。本文定义一次完整交付的范围，不拆分开发阶段，不设置“后续再补”的必需功能。本文交付不等于软件功能已经实现。

**交付目标：用户从空白画布出发，能够独立完成精确绘图、尺寸约束、轮廓编辑、二维成面、孔洞与区域运算、几何检查、保存恢复及文件交换。全部规定功能和验收用例通过，才认定建模模块完成。**

本文中的功能模块是同一交付物的组成部分，没有先上线简化版、再补齐核心能力的安排。实现过程中允许按依赖顺序编写和调试，但对用户只提交一套完整、可使用的建模程序。

**1．范围、边界与完成定义**

1. 只开发 XY 平面内的二维几何建模，所有几何的 Z 坐标为 0。
2. 包含自由草图、精确尺寸、持续约束、二维轮廓、面与孔洞、几何命名、图层、文件保存和交换。
3. 建模界面不出现密度、黏度、雷诺数、网格尺寸、速度、压力等物理参数；不扩展网格、求解、后处理、三维实体或装配功能。
4. 不修改主页背景、主页交互、知识库内容、登录状态或站点配色。建模画布使用静态白底、浅灰辅助线与蓝色操作反馈。
5. 几何可以命名为“入口边”“出口边”“障碍物”，这些仅为点、边、面的分组标签，不赋予物理含义。
6. 保留现有仿真程序入口和数据；建模完整保存后是否被现有求解器支持，应由单独的兼容性检查决定。不得把任意新模型偷换成外接矩形传给旧求解器。
7. 本交付必须包含椭圆、样条、修剪、延伸、圆角、偏移、布尔运算、持续约束、自动保存和 DXF 交换，不得用按钮占位或仅弹提示代替实现。
8. 明确不纳入：DWG、SpaceClaim 原生文件、三维 STEP/IGES 模型、任意 CAD 外部链接、曲面、实体拉伸和多用户协作。对这些输入明确报告不支持，不伪造转换成功。
9. 样条支持范围、工具适用对象和文件交换范围均在本文明确给出；范围外的组合禁用并说明原因，不隐式近似或删除对象。

交付完成必须同时具备：可运行程序、全部源码、锁定的依赖、示例模型、自动化测试、实际浏览器操作记录、性能记录、用户操作说明和第三方依赖说明。不能以通过编译、按钮齐全或截图美观代替功能验收。

**2．现有代码的处理范围**

编制时已核对的事实：现有技术栈为 Nuxt 3、Vue 3、Pinia 和 TypeScript；草图主组件为 `components/CfdSketcher.vue`，几何工具位于 `utils/sketch-geometry.ts`，入口位于 `components/pages/SimulationWorkbenchPage.vue`。

| 现状 | 必须执行的改造 |
|---|---|
| 草图对象和历史记录保存在组件内部 | 提升到独立文档仓库，组件卸载不销毁文档 |
| 只向父组件传宽高与对象数量 | 改为文档编号、版本和建模摘要；完整几何由文档仓库管理 |
| `constraints: string[]` 只表达标签 | 替换为包含类型、引用对象、数值和状态的约束记录 |
| 固定 300 × 190 的工作范围 | 改为可平移、缩放的模型坐标视图，不限制到原工作区 |
| 矩形和多边形被当作特殊外框处理 | 建立真实的边与轮廓；矩形和规则多边形保留生成参数 |
| 修剪只覆盖有限的直线情况 | 接入统一曲线求交、分割和区间删除机制 |
| 闭合轮廓通过对象数及连接图估算 | 替换为几何连接和拓扑判定，实际构建面及孔洞 |
| 模型区包含物性、方程和求解入口 | 提供专注绘图的完整建模工作区 |
| 旧文件格式为 `cfdrookie-sketch/2.0` | 提供明确的导入迁移，不把旧约束标签视为真实约束 |

`sources/` 中的同步资料保持只读。不改动现有知识库数据库、不读取或写入密钥配置、不将用户本机草稿作为源码提交。

**3．界面布局与操作契约**

建模入口保留在现有网站中，进入后展示独立的建模工作区。模型区占满可用内容高度，不再被物性表格和重复说明挤占。

| 区域 | 内容 | 行为 |
|---|---|---|
| 顶部第一行 | 文件名、保存状态、撤销、重做、打开、保存、导入、导出 | 未保存时显示状态；新建和打开不能静默覆盖未保存文档 |
| 顶部工具区 | 选择、绘制、修改、约束、区域、检查 | 分组展开；常用工具直接可见；图标配短文字和快捷键提示 |
| 左侧 | 模型树、草图、区域、图层、几何分组 | 支持重命名、显隐、锁定、定位；折叠后扩大画布 |
| 中央 | 几何、网格、坐标轴、吸附标记、预览、尺寸 | 画布只承载建模信息，不播放背景动画 |
| 右侧 | 选中对象属性或当前命令参数 | 随选择变化；多选时显示共同属性；可折叠 |
| 底部 | 当前操作提示、坐标、单位、吸附开关、约束状态 | 提示下一步动作；错误可定位到对象 |

桌面宽度不小于 1280 CSS px 时，两侧栏默认宽度分别为 220 px 和 280 px，均可收起；画布宽度不得低于 640 px。宽度为 900–1279 px 时右侧栏默认收起。小于 900 px 时面板改为抽屉或底部面板，不把画布挤成窄条。正文和输入文字原则上不小于 14 px，辅助文字不小于 12 px；触摸主要按钮目标不小于 44 × 44 CSS px。

选择与视图规则：

- 单击对象为替换选择；Shift 单击为追加或取消该对象；单击空白清空选择。
- 过滤器支持全部、点、边、轮廓、面、尺寸和约束；选中对象类型影响可用命令。
- 左向右框选只选择完全包含的对象；右向左框选选择相交对象；两种框采用不同线型和浅色填充。
- 重叠对象使用 Alt 单击轮换，触屏长按弹出候选列表；候选按距指针距离、对象层级和稳定编号排序。
- 悬停、选中、将删除、命令预览使用不同反馈；颜色之外增加线型或图标提示。
- 滚轮围绕鼠标位置缩放；中键或按住空格拖动平移；触屏双指缩放和平移。
- 缩放和平移不得改变任何模型数值；适合窗口根据可见模型的边界计算，并保留 10% 留白。
- 绘图中可临时平移和缩放，返回后继续原命令，不丢失已输入的点。
- 可见但锁定的对象可选择和测量，不可被任何修改命令更改；隐藏对象不参与拾取和吸附。
- 绘图鼠标操作统一走 Pointer Events；在画布外松开指针也能正确结束拖动；失去窗口焦点时清理按键和指针捕获。
- 单指触摸在选择工具中使用明显的拖动阈值；双指手势不创建几何。移动端提供所有精确命令的数值输入入口。

统一快捷键：V 选择，L 直线，P 连续线，R 矩形，C 圆，A 圆弧，D 尺寸，T 修剪，O 偏移，F 适合窗口，Delete 删除，Ctrl/Cmd+Z 撤销，Ctrl/Cmd+Shift+Z 重做，Ctrl/Cmd+S 保存草稿，Ctrl/Cmd+O 打开文件。Tab 在当前命令的数值字段间切换；Esc 先取消当前未提交操作，再返回选择工具。文本输入和中文输入法组合期间不触发绘图快捷键。

每个命令具有 `idle → collecting → previewing → committing → idle` 状态。选择不足、参数错误、运算失败都必须停留在可修改状态；Esc 恢复到操作前；提交后才生成一条撤销记录。

**4．坐标、单位、精度和数值输入**

- 内部几何统一使用毫米和弧度，双精度数值；界面支持 mm、cm、m 和度。
- 建模坐标 X 向右、Y 向上，原点可见；显示单位切换仅改变数值表达，不改变模型实体大小。
- 使用统一的世界坐标与屏幕坐标矩阵及其逆矩阵。CSS 缩放、设备像素比和画布布局留白必须纳入转换，不能仅用外接框宽高作比例换算。
- 支持负坐标；网格覆盖当前可视范围，间距按 1、2、5 乘以 10 的整数次幂调整，避免缩小时出现密集闪烁。
- 默认数值几何容差 `ε = max(10^-6 mm, 10^-9 × L)`，其中 L 为本次操作输入包围盒对角线，至少取 1 mm。该容差用于数值判定，不代表允许自动移动或合并端点。
- 单次命令计算开始后固定其容差；所有参与该命令的算法使用同一个值。不能在同一运算中不断改变容差。
- 用户修复容差单独存储，默认 0.01 mm；只有用户确认修复才允许按此距离合并端点。
- 新建边长度须大于 10ε；半径、椭圆半轴必须大于 10ε。零长度、非有限数值和退化轮廓拒绝提交。
- 角度与归一化方向判定的默认容差为 10^-8 rad；长度残差按 ε 校验。求解器采用局部坐标和尺度归一化，输出后仍按毫米与弧度独立复核，不能把无量纲求解残差直接解释成毫米误差。
- 模型支持的几何尺度范围为 0.001 mm 至 1,000,000 mm；坐标绝对值不大于 1,000,000,000 mm。范围边界校验必须给出数值和单位，不能偷偷截断。几何运算在局部原点附近进行，结果再平移回去。

输入支持绝对 X/Y、相对 ΔX/ΔY、长度与角度、半径与直径；绘制中可输入并锁定一个字段再指定另一个。单位后缀可直接输入，例如 `25 mm`、`0.2 m`。精度显示可调整，但模型内部不按显示小数位截断。

参数表达式只支持数字、已定义参数、括号、加减乘除、正负号及单位，禁止执行 JavaScript。校验量纲、除零、未定义引用和循环引用。例如长度参数 `喉宽 = 入口宽 / 2` 有效，`入口宽 + 30 deg` 无效。角度内部转为弧度，界面默认使用度；无单位字面量在单一数值字段中采用当前显示单位，在参数表达式中按无量纲常数处理。

**5．必须交付的绘图工具**

| 编号 | 工具 | 输入方式与编辑能力 | 提交条件 |
|---|---|---|---|
| DRAW-01 | 点 | 单击或精确坐标；可移动、命名和用作构造点 | 坐标有效 |
| DRAW-02 | 直线 | 两点；起点加长度角度；水平、竖直方向追踪 | 两端不重合 |
| DRAW-03 | 连续线 | 连续单击；Enter 结束；显式闭合；Backspace 撤回最后一个预览点 | 每段有效；保留顺序与连续关系 |
| DRAW-04 | 矩形 | 对角点、中心和宽高、三点旋转矩形 | 四边真实存在；保留矩形尺寸及垂直、平行关系 |
| DRAW-05 | 圆 | 圆心半径、圆心直径、三点定圆 | 半径有效；三点不共线 |
| DRAW-06 | 圆弧 | 圆心起终点、三点圆弧、从已知端点和切向绘制相切圆弧 | 弧向明确；不能以相同端点隐式表示整圆 |
| DRAW-07 | 多边形 | 任意连续顶点；规则多边形的中心、边数、半径和起始方向 | 规则多边形 3–256 边；闭合时检查自交 |
| DRAW-08 | 槽形 | 两端圆心和宽度；中心、总长、宽度和方向 | 长度不小于宽度；两直边与半圆相切 |
| DRAW-09 | 椭圆 | 中心、长短半轴、方向；拖动轴端点；数值修改 | 半轴有效；旋转后形状不变 |
| DRAW-10 | 样条 | 三次非有理 B 样条；控制点方式和经过点方式；开放或闭合 | 控制点、节点和闭合规则有效 |
| DRAW-11 | 构造几何 | 点、线、圆、轴线可切换为构造对象 | 参与吸附、测量和约束，不参与成面 |

三点圆弧必须经过中间点，用该点确定大弧/小弧和方向；圆心方式显示方向切换。圆弧镜像后保留真实起终点、扫角绝对值和对应方向，不能变成补弧。

样条采用明确的能力边界：创建非有理三次 B 样条；支持控制点拖动、增删控制点后重新拟合、插入节点保持形状、端点位置和端部切向控制；闭合模式至少保证位置连续，可选周期平滑闭合。导入时可保留最高五次的有理 B 样条和权重；权重可数值修改。超出五次或数据无效的曲线报告不支持，不偷偷离散化。

矩形、规则多边形和槽形创建后生成真实边及对应关系。树中可作为组合对象选择，也可单独选中边；拆解仅解除组合关系，不删除几何。若拆解会影响生成参数，预览中显示哪些参数关系将解除。

**6．吸附、追踪和手柄**

吸附类型：端点、中点、圆心、椭圆中心、圆与椭圆象限点、交点、垂足、切点、网格点。样条支持端点、控制点、曲线上最近点和可求出的交点；不把采样折线的顶点冒充曲线特征点。

鼠标吸附半径默认 10 CSS px，触摸默认 18 CSS px；用于拾取的距离可稍大，但不得改变几何容差。候选同等接近时按端点、交点、中点、中心、垂足/切点、曲线上点、网格排序。显示候选类型和标记，支持候选轮换；Ctrl 按住临时关闭吸附，不与 Shift 多选混用。

水平、竖直和固定角度追踪独立于网格；追踪角默认 15°，用户可修改。没有可用精确交点时，不用网格点覆盖已明确输入的尺寸。

吸附“位置”与添加“约束”分开：普通吸附确定当前坐标；开启自动约束后，端点重合、水平、竖直、相切等关系以可见约束图标预览，提交时创建真实关系。冗余关系不重复添加。自动约束开关随文档保存。

点、端点、圆心、半径、圆弧起终点、椭圆轴端点及样条控制点提供编辑手柄。拖动手柄通过约束系统求解，不绕过约束直接写入坐标；显示可移动方向和不允许移动的原因。

**7．修改工具的完整行为**

| 编号 | 功能 | 必须实现的行为 |
|---|---|---|
| EDIT-01 | 移动 | 拖动、位移输入、基点到目标点；多选整体移动；支持保留原件 |
| EDIT-02 | 旋转 | 任意中心和角度；顺逆时针；可旋转复制；矩形和多边形真实转动 |
| EDIT-03 | 镜像 | 已有直线或两点定义任意镜像轴；可保留原件；弧向正确 |
| EDIT-04 | 缩放 | 指定基点和正的统一比例；圆保持圆；不提供隐式非均匀缩放 |
| EDIT-05 | 矩形阵列 | 行列数量、两个方向与间距；预览全部结果；默认保留同一阵列特征 |
| EDIT-06 | 圆周阵列 | 中心、数量、总角度或步进角、随阵列旋转方向开关；整圆不重复首尾对象 |
| EDIT-07 | 修剪 | 在交点处分割，删除指针所在的局部区间；确认前红色预览；支持直线、圆、圆弧、椭圆、样条 |
| EDIT-08 | 延伸 | 直线沿方向延长；圆弧和椭圆弧沿其母曲线延长到选定边界；显示多个交点候选 |
| EDIT-09 | 分割 | 在指定点、曲线参数或全部交点处分割；圆分割为圆弧；参数区间和来源可追踪 |
| EDIT-10 | 圆角 | 两相交直线、直线与圆/圆弧、两圆/圆弧之间的定半径圆角；选定连接分支，自动修剪连接 |
| EDIT-11 | 倒角 | 两条相交直线；双距离或距离加角度；数值预览与有效性检查 |
| EDIT-12 | 偏移 | 直线、圆、圆弧和由这些边组成的整条轮廓等距偏移；椭圆/样条输出内核偏移曲线或满足误差限制的样条 |
| EDIT-13 | 合并 | 将端点连通的边组织成轮廓；共线相邻直线、同圆相邻圆弧可合并；不得吞掉分支 |
| EDIT-14 | 拆解 | 组合、轮廓和阵列可拆解成独立可编辑对象；保留位置与几何 |
| EDIT-15 | 删除 | 预览受影响的约束、尺寸、分组与下游区域；一次确认，整个操作可撤销 |

适用范围规定：延伸不对整圆、完整椭圆或任意样条作猜测性外推；这些对象仍支持修剪和分割。圆角不承诺任意样条与样条之间的曲率连续过渡；倒角只适用于直线对。选中不适用对象时解释具体原因，禁止调用“删除整个对象”作为替代行为。

修剪规则：求得精确或经误差验证的交点，按曲线参数排序并去重，再选取指针命中的区间。没有分割边界时提示“没有可修剪区间”，提供显式删除命令，不能直接删除整个对象。圆只有一个切触点不能自动推导两个有效弧段。

偏移规则：开放线链显示左/右，闭合轮廓显示内/外；连接支持圆角、斜接和截角，斜接长度默认上限为偏移距离的 4 倍。凹角、自交和内缩消失必须检查；允许得到多个有效轮廓时，让用户预览并选择保留结果。偏移不是缩放外接圆，也不是简单放大包围盒。

椭圆和样条偏移如需拟合，结果必须标记为“近似曲线”，记录最大偏差，默认限值为 `max(10ε, 0.001 mm)`，并通过自适应细分及曲率/包围盒误差界验证；仅比较若干均匀采样点不算误差证明。超过误差阈值则失败，不声称精确。用户可在命令面板收紧阈值。

复制默认生成独立副本，内部约束一起复制并重映射编号，指向未复制对象的外部约束默认不复制并在预览说明；保留外部关联须显式选择。移动、旋转、缩放遇到驱动尺寸或外部约束时先求解预览；不满足时可取消或显式解除列出的约束，不能暗中删除约束。缩放驱动尺寸需要明确选择同步缩放相关长度参数；角度和无量纲参数不变。

阵列数量范围 1–1000，总生成对象数受文档上限限制。阵列副本通过特征生成，修改原件或阵列参数时重算；编辑单个实例前提供“解除该实例关联”，不把一次性复制伪装成关联阵列。

**8．尺寸、约束与参数化修改**

所有约束以稳定编号引用几何，持久保存。一个约束至少记录类型、引用、驱动状态、表达式/数值、启用状态及诊断。文字标签仅用于显示。

| 编号 | 约束 | 适用范围 |
|---|---|---|
| CON-01 | 重合、点在线/曲线上 | 点与点、点与支持的曲线；支持线段内部及曲线参数域检查 |
| CON-02 | 水平、竖直 | 直线或两点关系 |
| CON-03 | 固定 | 点或完整几何对象；不等同于图层锁定 |
| CON-04 | 平行、垂直 | 两条直线 |
| CON-05 | 等长 | 两条直线；圆弧等长不在此类型中混用 |
| CON-06 | 同心、等半径 | 圆和圆弧；椭圆可同心但不使用等半径 |
| CON-07 | 相切 | 直线与圆/圆弧、圆弧对、椭圆与直线；样条端部切向与直线关系 |
| CON-08 | 对称、中点 | 点对关于直线对称；点在线段中点；组合可展开成多条明确关系 |
| CON-09 | 长度、距离 | 线长、点距、水平/竖直距离、点到直线距离；有向距离显式区分 |
| CON-10 | 半径、直径 | 圆和圆弧；椭圆采用长短半轴尺寸 |
| CON-11 | 角度 | 两直线之间或直线与坐标轴之间；固定所选角度分支 |
| CON-12 | 参考尺寸 | 全部支持对象的测量值，仅显示，不加入驱动约束 |

驱动尺寸以实际标注呈现在画布，尺寸线可移动，标注偏移以屏幕长度保存以免缩放后过大。双击数值进入修改；几何被遮挡时标注可隐藏或单独选中。参考尺寸带明显标识。

求解流程：在操作前模型的副本上应用参数变化；检查参数依赖无环；将受影响的约束连通分量提交给求解器；获得候选解；检查几何不变量、残差及方向分支；成功后提交整个事务。失败时保留原模型，显示冲突或未收敛原因。

编辑锁定和几何固定的含义不同：锁定属于操作权限状态，可随时解锁，不增加永久约束；但在任何当前求解事务中，被锁定对象的现有变量必须作为不可修改量处理。若修改其他尺寸要求移动锁定对象，则该命令失败并指出对象，不能通过联动求解绕过锁定。

用户拖动采用临时目标，不把指针位置变成永久尺寸。先以现有解为初值，保持原圆弧方向、轮廓方向与可追踪的解分支；不能为了满足距离突然镜像整个模型。结束拖动后验证永久约束再提交。

“完全约束”只在永久约束残差满足要求、自由度为 0 且无冲突时显示；临时拖动目标不计入。欠约束显示可自由变化的数量；不能取得可靠自由度时显示“状态未确定”，不能编造数值。冲突提示至少给出包含冲突的一组约束，不声称一定是最小冲突集。重复约束单独提示并允许保留为参考标注。

参考尺寸直接由几何测量计算，不依赖求解器的非驱动约束结果；所选 PlaneGCS 封装的文档列出了部分非驱动约束的限制，不能直接透传为本产品功能。[PlaneGCS 项目说明](https://github.com/Salusoft89/planegcs)

参数表包含名称、表达式、量纲、当前值和使用位置。参数可以使用中文，但编号独立于名称；重命名更新引用；删除被引用参数须列出影响，不生成未定义表达式。参数循环拒绝提交。测量值不能反向驱动同一条依赖链形成循环。

**9．轮廓、区域、孔洞和几何检查**

所有生成的区域必须有可遍历的边界，不允许仅用 SVG 填色冒充面。

成面流程：排除构造和隐藏于其他草图但未引用的对象 → 求交并构建分割边 → 建立顶点和有向边 → 识别候选闭环 → 检查自交及退化 → 判定包含关系 → 建立外边界与孔洞 → 校验二维面 → 生成可选择的区域。

草图原始对象在成面时不被偷偷打断；用于区域拓扑的分割边作为派生结果，记录来源曲线和参数区间。闭环外边界统一为逆时针，孔洞为顺时针，方向指建模坐标而非屏幕坐标。轮廓嵌套按包含层级区分孔洞和岛，不以颜色或面积大小猜测。

| 编号 | 功能 | 输出 |
|---|---|---|
| FACE-01 | 识别轮廓 | 有效闭环、开口链和错误位置 |
| FACE-02 | 生成面 | 用户选定的区域，可含孔洞 |
| FACE-03 | 并集 | 合并的一个或多个面；不相连输入可以保留多个区域 |
| FACE-04 | 差集 | 从目标面扣除工具区域，方向明确 |
| FACE-05 | 交集 | 面积重叠区域；只接触点或边时报告没有面积交集 |
| FACE-06 | 分割面 | 直线或曲线切穿区域后形成多个可独立选择的面 |
| FACE-07 | 几何分组 | 稳定引用点、边和面；名称及显隐可编辑 |
| FACE-08 | 测量 | 长度、距离、夹角、周长、面积、面积重心、包围尺寸 |

面运算使用同一 XY 平面上的有效面。目标和工具可通过命令面板互换。默认保留源草图和运算关系、隐藏被替代的输出；不得删除构造依据。尺寸变化后按依赖重建区域，失败时显示上一个有效结果的灰色预览并标记“已失效”，禁止将其作为当前有效模型导出。

拓扑引用使用来源特征、来源曲线、参数区间和生成关系识别。曲线分割后，一个边分组可以映射为多个子边；目标被删除则标记失效；存在多个无法唯一判断的候选时要求重新选择，不能仅凭最近距离把“入口边”迁移到另一条边。

几何检查必须列出问题类型、相关对象、位置、严重程度、修复建议；点击问题定位并高亮。包含：开口、重复/重叠边、自交、零长度、极短边、半径无效、相切退化、孔洞越界、孔洞接触外边界、失效引用及约束冲突。孔洞与外边界接触时不能仍标记为普通内部孔洞；若可转为有效开槽区域，应由布尔运算明确构建。

修复命令包含端点合并、删除重复边、去除明确的零长度对象、交点处分割、重建轮廓。每次修复显示容差和前后差异，可逐项勾选；修复导致已有约束或区域变化时列出影响。默认不在文件打开时自动修复。

面积和周长优先使用解析/内核计算。曲线近似参与计算时报告误差界；面积允许误差采用 `max(10ε × 周长, 10^-8 × 面积)`，长度允许误差采用 `max(10ε, 10^-8 × 长度)`。这些是验收阈值，不是将错误几何吸附到一起的许可。

**10．确定采用的技术方案**

继续使用项目现有的 Nuxt、Vue、Pinia 和 TypeScript。建模模块在客户端加载，渲染、交互、数据、约束和几何内核明确分离，不继续向一个巨型 Vue 组件内追加几何算法。

| 责任 | 方案 | 交付约束 |
|---|---|---|
| 界面与状态 | Vue 组件、Pinia 文档仓库 | 模型与界面生命周期分离 |
| 画布 | Canvas 2D 分层绘制几何和网格，SVG/HTML 覆盖尺寸、手柄及输入 | 绘制和拾取共用变换矩阵；Canvas 不作为几何数据源 |
| 约束求解 | `@salusoft89/planegcs@1.2.0`，独立 Worker | 包装为项目接口；不得将库的编号和内存对象泄漏到文档 |
| 几何与拓扑 | `opencascade.js@2.0.0-beta.b5ff984`，独立 Worker | 统一在 XY 平面工作；通过适配层调用；验证所需绑定 |
| 快速交互几何 | TypeScript 的包围盒、空间索引、解析直线/圆求交与屏幕拾取 | 快速预览必须由内核/数值验证后才能提交 |
| 本机存储 | IndexedDB | 原子保存文档、备份和版本；不把大模型塞进 localStorage |
| 文件交换 | 自有 JSON、受限 ASCII DXF、受限 SVG 解析和写出 | 明确支持对象；解析与校验分离；不假定 OCCT 自带免费 DXF 导入器 |
| 验证 | 现有 tsx 测试体系，加浏览器操作测试 | 内核集成测试必须使用真实 WASM，不能全用模拟结果 |

两项 WASM 包的上述精确版本在编制时已核对公开包记录存在。OpenCascade.js 选定版本属于 beta，不能当作已验证的稳定集成；固定版本、适配层和真实内核契约测试是本次交付要求。此文未安装依赖或证明其已在当前项目运行。

OpenCascade.js 提供 OCCT 的 JavaScript/WebAssembly 接入；可采用完整构建作为基准，所需接口缺失时通过同源固定版本构建补齐绑定，不能删去必需功能。[OpenCascade.js 官方说明](https://ocjs.org/) [自定义构建说明](https://ocjs.org/docs/app-dev-workflow/custom-builds)

PlaneGCS 的浏览器封装提供二维约束求解及 TypeScript 接口。项目只在适配层使用其对象和编号，引用顺序、圆弧内部关系及资源释放均由适配层负责。[PlaneGCS 源码仓库](https://github.com/Salusoft89/planegcs) [版本记录](https://raw.githubusercontent.com/Salusoft89/planegcs/main/package.json)

几何内核适配层负责曲线求交、截取、最近点、长度、曲线偏移、构造线框与面、平面布尔运算、拓扑有效性和运算来源映射。OCCT 参考能力不能自动等同于所选 WASM 构建的实际可用绑定，必须逐项写集成测试。[OCCT 布尔运算说明](https://dev.opencascade.org/doc/overview/html/specification__boolean_operations.html)

依赖只在建模入口按需加载，从本站静态资源提供 WASM，不依赖运行时公共 CDN。Worker 采用单线程 WASM 实例，不要求为整个站点启用共享内存隔离。构建输出保留确定的资源路径、哈希与许可证信息；完整构建过大时可以裁剪，但功能与验收范围保持相同。

新增的第三方依赖保留来源、确切版本、锁文件和对应许可证。自定义构建还应交付构建配置、对应源码版本和修改记录。本文不对不同仓库文件间可能存在差异的许可证名称作推断，发布记录以实际分发文件为准。

整体数据方向如下，箭头表示数据流而非开发阶段：

```text
鼠标 / 键盘 / 属性面板
            ↓
命令控制器 → 草稿预览（可取消）
            ↓
约束求解 Worker → 几何/拓扑 Worker → 事务校验
                                        ↓
                           文档仓库（唯一有效模型）
                              ↓       ↓       ↓
                           渲染缓存  保存服务  历史记录
```

对不涉及约束和拓扑的操作可以跳过相应计算；显隐、选择、视图变化不触发整个模型重算。

**11．模型文件和核心数据契约**

项目文件扩展名为 `.cfd2d.json`，格式标识为 `cfdrookie-model2d`，结构版本为 1。项目结构版本与旧草图格式的数字互不对应。

以下为必须落实到 TypeScript 和运行时校验器的核心结构。类型表示项目自有数据，不是第三方库的直接对象；`Id` 使用 UUID，所有映射键与记录中的编号一致。

```ts
type Id = string
type Vec2 = { x: number; y: number }
type Unit = 'mm' | 'cm' | 'm'
type Quantity = 'length' | 'angle' | 'scalar'
type Direction = 1 | -1

interface EntityBase {
  id: Id
  sketchId: Id
  name: string
  layerId: Id
  construction: boolean
  locked: boolean
  visible: boolean
}

type Entity = EntityBase & (
  | { kind: 'point'; position: Vec2 }
  | { kind: 'line'; startPointId: Id; endPointId: Id }
  | { kind: 'circle'; centerPointId: Id; radius: number }
  | { kind: 'arc'; centerPointId: Id; radius: number;
      startAngle: number; sweepAngle: number }
  | { kind: 'ellipse'; centerPointId: Id; majorRadius: number;
      minorRadius: number; rotation: number }
  | { kind: 'ellipseArc'; centerPointId: Id; majorRadius: number;
      minorRadius: number; rotation: number;
      startParameter: number; sweepParameter: number }
  | { kind: 'bspline'; degree: number; controlPointIds: Id[];
      weights: number[]; knots: number[]; multiplicities: number[];
      periodic: boolean; closed: boolean }
)

interface GeometryRef {
  owner: 'sketch' | 'feature'
  ownerId: Id
  objectId: Id
  role: 'object' | 'point' | 'start' | 'end' | 'center'
    | 'midpoint' | 'edge' | 'face' | 'controlPoint'
  controlPointIndex?: number
  parameter?: number
}

type ConstraintKind =
  | 'coincident' | 'pointOnCurve' | 'horizontal' | 'vertical'
  | 'fixed' | 'parallel' | 'perpendicular' | 'equalLength'
  | 'concentric' | 'equalRadius' | 'tangent' | 'symmetric'
  | 'midpoint' | 'length' | 'distance' | 'distanceX' | 'distanceY'
  | 'pointLineDistance' | 'radius' | 'diameter' | 'angle'
  | 'ellipseMajorRadius' | 'ellipseMinorRadius'

interface Constraint {
  id: Id
  sketchId: Id
  kind: ConstraintKind
  refs: GeometryRef[]
  enabled: boolean
  expression?: string
  value?: { quantity: Quantity; canonicalValue: number }
  branch?: { signed: boolean; orientation: Direction; label: string }
}

interface Dimension {
  id: Id
  mode: 'driving' | 'reference'
  constraintId?: Id
  measure: 'length' | 'distance' | 'distanceX' | 'distanceY'
    | 'radius' | 'diameter' | 'angle' | 'area' | 'perimeter'
  refs: GeometryRef[]
  labelOffsetPx: Vec2
  visible: boolean
}

interface Parameter {
  id: Id
  name: string
  quantity: Quantity
  expression: string
}

interface Sketch {
  id: Id
  name: string
  entityIds: Id[]
  constraintIds: Id[]
  visible: boolean
  locked: boolean
}

interface Wire {
  id: Id
  name: string
  edges: { ref: GeometryRef; direction: Direction }[]
  closed: boolean
}

interface Layer {
  id: Id
  name: string
  visible: boolean
  locked: boolean
  color: string
  order: number
}

interface GeometryGroup {
  id: Id
  name: string
  refs: GeometryRef[]
  visible: boolean
}

interface FeatureBase {
  id: Id
  name: string
  enabled: boolean
  inputs: GeometryRef[]
}

type Feature = FeatureBase & (
  | { kind: 'profile'; selectedCells: Id[] }
  | { kind: 'boolean'; operation: 'union' | 'difference' | 'intersection';
      targetInputIds: Id[]; toolInputIds: Id[] }
  | { kind: 'splitFace'; faceInputIds: Id[]; cutterInputIds: Id[] }
  | { kind: 'offset'; distanceExpression: string;
      side: 'left' | 'right' | 'in' | 'out';
      join: 'round' | 'miter' | 'bevel'; miterLimit: number;
      maxApproximationErrorMm: number; selectedResultIds: Id[] }
  | { kind: 'arrayRect'; rows: number; columns: number;
      direction1: Vec2; direction2: Vec2;
      spacing1Expression: string; spacing2Expression: string }
  | { kind: 'arrayPolar'; center: Vec2; count: number;
      totalAngleExpression: string; fullCircle: boolean;
      rotateInstances: boolean }
)

interface TopologyName {
  id: Id
  ownerFeatureId: Id
  kind: 'vertex' | 'edge' | 'face' | 'cell'
  sources: {
    ref: GeometryRef
    interval?: [number, number]
    relation: 'unchanged' | 'split' | 'merged' | 'generated'
  }[]
  boundaryIds: Id[]
}

interface Model2DDocument {
  format: 'cfdrookie-model2d'
  schemaVersion: 1
  id: Id
  name: string
  revision: number
  createdAt: string
  updatedAt: string
  internalLengthUnit: 'mm'
  displayLengthUnit: Unit
  displayAngleUnit: 'deg'
  tolerance: { absoluteMm: number; relative: number; repairMm: number }
  sketches: Record<Id, Sketch>
  entities: Record<Id, Entity>
  constraints: Record<Id, Constraint>
  dimensions: Record<Id, Dimension>
  parameters: Record<Id, Parameter>
  wires: Record<Id, Wire>
  features: Record<Id, Feature>
  topologyNames: Record<Id, TopologyName>
  layers: Record<Id, Layer>
  groups: Record<Id, GeometryGroup>
  preferences: {
    autoConstraint: boolean
    gridVisible: boolean
    snapKinds: string[]
    angleIncrementDeg: number
  }
  view: { center: Vec2; pixelsPerMm: number }
}
```

运行时校验必须按每种约束定义引用数量和角色，例如平行约束必须引用两条直线；不能只检查字段是否存在。表达式和数值同时存在时，表达式为输入，数值仅为解析缓存，加载时必须重算校验。所有 Entity 中的坐标与曲线数值是最近一次提交的有效解，不能依赖界面字段重建。

圆弧采用带符号的扫角，绝对值严格小于 2π 且大于角度容差；整圆使用 circle。起终点由中心、半径及参数推导，避免端点和圆弧定义相互矛盾；求解器需要独立端点时由适配层创建内部变量和必要关系。

样条保存实际控制点、权重、节点及重数，检查其数量关系、递增顺序、权重正值和周期规则。点对象的共享引用表示同一个几何点；两个独立点重合则通过约束表达。删除共享点必须显示被引用的几何，不能留下断引用。

矩形、规则多边形和槽形通过实体集合、Wire 和约束表达，尺寸参数通过约束绑定。圆角作为真实新增圆弧、半径尺寸及相切关系保存；修剪和分割直接修改源草图并记录来源映射，不需要把每次鼠标点击都永久保留为特征。

成面、布尔、偏移和阵列使用 Feature 记录可重算关系。`inputs` 中对象编号在一条特征内必须唯一；target/tool/cutter 等字段引用这些输入的 objectId。若需要同一对象的不同子对象，应创建不同的稳定子对象编号。特征依赖构成有向无环图。输出几何放在运行时缓存中，稳定编号及来源关系写入 `topologyNames`。

特征生成对象默认通过源草图或特征参数编辑，属性面板提供“定位来源”。需要直接修改结果时，使用显式“转为独立几何”，将有效结果转换为支持的实体和轮廓，列出将解除的关联后一次提交；不得让用户拖动渲染缓存而下次重算又恢复。近似结果的误差、来源及验证方法写入特征重建诊断，文件重新打开后必须重新计算和核验，不能把旧诊断当作永远有效。

`selectedCells` 与 `selectedResultIds` 引用持久化的拓扑名称，而不是每次遍历生成的数组下标。第一次创建时给候选单元分配稳定编号；几何变化后通过来源链重新匹配；结果消失或无法唯一匹配时标记待重新选择，不能静默选择面积相近的区域。

运行时另外保存求解诊断、有效/失效区域、内核句柄、空间索引、渲染缓存、选择集、命令草稿和撤销记录。这些不直接写入主项目文件；内核对象尤其不能 JSON 序列化。项目文件可保存有错误的草图以便修复，但必须通过结构和引用校验；几何导出仅允许选中的有效结果。

文档中的 `revision` 单调增加；撤销也产生新修订号，避免旧 Worker 响应覆盖撤销后的状态。文档有修改但未保存时显示真实的保存状态。

**12．命令、内核、线程和错误协议**

模块间使用项目自定义接口，不让 Vue 组件直接操纵 OCCT 或 PlaneGCS 的对象。

```ts
type ProblemCode =
  | 'INVALID_INPUT' | 'INVALID_REFERENCE' | 'UNSUPPORTED_GEOMETRY'
  | 'LOCKED_OBJECT' | 'DEGENERATE_GEOMETRY' | 'NO_INTERSECTION'
  | 'OPEN_WIRE' | 'SELF_INTERSECTION' | 'INVALID_FACE'
  | 'CONSTRAINT_CONFLICT' | 'SOLVER_DID_NOT_CONVERGE'
  | 'APPROXIMATION_LIMIT' | 'AMBIGUOUS_TOPOLOGY'
  | 'DEPENDENCY_CYCLE' | 'STALE_REVISION' | 'RESOURCE_LIMIT'
  | 'CANCELLED' | 'WORKER_FAILED' | 'STORAGE_FAILED'

interface ModelingProblem {
  code: ProblemCode
  message: string
  refs: GeometryRef[]
  location?: Vec2
  details: Record<string, string | number | boolean>
}

type OperationResult<T> =
  | { ok: true; value: T; warnings: ModelingProblem[] }
  | { ok: false; errors: ModelingProblem[] }

interface WorkerRequest<T> {
  protocolVersion: 1
  requestId: Id
  documentId: Id
  baseRevision: number
  kind: string
  payload: T
}

interface WorkerResponse<T> {
  requestId: Id
  documentId: Id
  baseRevision: number
  result: OperationResult<T>
}
```

| 接口责任 | 必须提供的方法或等价命令 |
|---|---|
| 坐标服务 | `worldToScreen`、`screenToWorld`、`zoomAt`、`fitVisible` |
| 拾取服务 | `hitTest`、`queryWindow`、`queryCrossing`、`getSnapCandidates` |
| 文档命令 | `begin`、`preview`、`commit`、`cancel`、`undo`、`redo` |
| 约束适配层 | `validateRefs`、`solve`、`drag`、`getDiagnostics`、`measure` |
| 几何适配层 | `intersect`、`project`、`split`、`trim`、`offset`、`fillet`、`buildRegions`、`boolean`、`splitFace`、`measure`、`validate` |
| 特征重建 | `resolveDependencies`、`rebuildAffected`、`mapTopology` |
| 文档存储 | `saveDraft`、`loadDraft`、`listDrafts`、`recoverPrevious`、`downloadProject` |
| 文件交换 | `parse`、`validateImport`、`previewImport`、`applyImport`、`export` |

这些名称为本项目接口，不能假定与第三方库方法同名。适配层负责对应到固定版本的真实绑定；接口返回值必须使用可序列化的几何、引用和诊断，不传递 WASM 指针。

命令事务保存正向修改和逆向修改；一次操作产生一条历史记录。预览可被丢弃，不改变已提交文档。连续数值输入防抖预览，但 Enter 必须等待与最新输入一致的验证结果。

主线程接收响应时同时核对 documentId、baseRevision 和 requestId；旧文档、旧版本及旧预览响应全部丢弃。几何和求解 Worker 各保持一个活跃重计算任务；排队预览只保留最新一项，最终确认命令不能被预览挤掉。

WASM 同步运算不一定能在内部响应取消。超过 150 ms 显示可取消的忙碌状态；取消时先使该请求失效，必要时终止对应 Worker，再从最近有效文档重建。内核错误、内存不足和 Worker 崩溃不能导致主文档丢失。

所有内核临时对象在成功和失败路径释放；缓存被替换时释放原对象；退出建模模块时保留模型文档但释放大型渲染和内核资源。浏览器再次进入时可从规范数据重建，不依赖上次的内存地址。

提交前验证：数据结构 → 引用与依赖 → 约束 → 几何不变量 → 受影响区域。显式删除或修剪允许将草图变为未闭合，但必须标记下游区域失效，不能将旧面继续标记为有效。

**13．保存、恢复和旧文件迁移**

每个文档使用独立编号。空白模型默认无几何，不再自动生成一个有限大小的矩形计算域。工具示例通过独立的“打开示例”入口加载，不强加给新模型。

保存规则：

1. 提交操作后 500 ms 防抖自动保存到 IndexedDB；一次拖动保存一次。
2. 只有 IndexedDB 事务完成后才显示“已保存至本机”；磁盘项目文件另用“下载项目”导出，不能把本机草稿状态误写为已写入用户硬盘文件。
3. 保存结构为当前有效快照、上一个有效快照和必要的修订元数据；主快照切换原子完成。
4. 撤销记录在当前会话保留至少 200 条普通操作；大事务采用修改记录，不能为每次鼠标移动复制整份文档。超过内存预算时只释放最旧记录并提示可撤销范围。
5. 浏览器刷新后恢复模型、视图、图层和参数；不承诺恢复未提交预览，也不承诺恢复全部会话撤销记录。
6. 存储额度不足时显示未保存状态，提供下载项目；不能弹出“保存成功”。
7. 多标签页打开同一个文档时，以文档租约和版本检查防止相互覆盖；只允许一个写入者，另一个提供只读或另存副本。
8. 下载与导入都检查文件名、格式版本、内容长度和对象数量；打开新文档前保留现有未保存草稿。

旧版 `cfdrookie-sketch/2.0` 导入规则：

- 校验 unit 和所有数值；已知旧版单位为 mm。缺失单位时显示迁移选项，用户选定后继续，不猜成米。
- 旧屏幕坐标 Y 向下，新坐标 Y 向上，默认采用 `x_new = x_old`、`y_new = -y_old`；导入后适合窗口，保持视觉形状。可另设平移原点，但不能改变实际尺寸。
- 直线迁移为端点和边；矩形迁移为四条有方向边及矩形关系；规则多边形按旧显示方向生成实际顶点，不能丢失旧版默认顶点朝向。
- 圆心 Y 取反；圆弧起角取反、扫角取反。旧弧扫角必须按旧渲染规则计算后再变换，不能只交换起终角。
- `locked` 迁移为编辑锁定，不自动增加几何固定约束。
- 旧约束字符串仅写入迁移报告。可由可验证的矩形生成规则建立新关系，但不推测任意两条线之间存在旧标签所说的约束。
- 旧 `domain` 转为名为“原计算域”的几何分组；有效闭合时允许建立区域，不限制它必须是整个模型唯一的矩形。
- 重复编号重新分配并记录映射；不接受 NaN、Infinity、非法半径或失效对象。错误导入不会替换当前模型。
- 导入完成后显示对象数量、迁移警告和几何检查结果；原文件内容保持不变。

更老或未知草图版本报告不支持的具体版本，不能只凭格式前缀相同就按 2.0 猜测结构。

**14．DXF、SVG 和项目文件的交换规格**

| 格式 | 导入 | 导出 | 必须保留或说明 |
|---|---|---|---|
| `.cfd2d.json` | 完整文档校验与恢复 | 完整模型、约束、参数、特征、分组和视图 | 保持可编辑性，结构版本可校验 |
| ASCII DXF | POINT、LINE、CIRCLE、ARC、ELLIPSE、LWPOLYLINE、二维 POLYLINE、SPLINE | 相同基本几何与图层；采用 AC1027/R2013 | 单位、弧段、方向、闭合标志；不携带本项目约束 |
| SVG | line、rect、circle、ellipse、polyline、polygon、path 的 M/L/H/V/C/S/Q/T/A/Z | 二维轮廓、有效区域和可选标注 | 几何交换，不承诺参数化信息往返 |

DXF 的支持细则：

- 只接受 XY 平面对象；有非零高程、非 XY 法向或三维多段线时明确拒绝该对象并给出报告，不默默投影。
- 解析 HEADER 的单位。单位为未指定时，导入面板必须选择单位后才能应用；界面默认建议 mm，但未确认不提交。
- LWPOLYLINE/POLYLINE 的 bulge 应还原圆弧，保留正负方向，不能当成直线连接。
- ELLIPSE 的参数区间可生成完整椭圆或椭圆弧。SPLINE 还原次数、节点、重数、控制点、权重与闭合状态，遵循本文五次上限。
- 基本 BLOCK/INSERT 支持递归展开、平移、旋转和统一缩放，最大嵌套 16 层；循环引用拒绝；非均匀比例 INSERT 明确报告不支持，不变形成错误圆。
- 二维图层名称、颜色和可见状态保留。TEXT、MTEXT、DIMENSION 和 HATCH 计入忽略清单，不冒充已经转换成建模对象。
- 有不支持对象时先展示“可导入/忽略/失败”数量，用户确认才导入可支持部分；用户也可取消。不能无声漏图。
- 写出闭合多段线时不重复首尾顶点；写出圆和圆弧使用原生实体；一般样条使用 SPLINE，不无条件离散化。

SVG 的支持细则：

- 应用嵌套变换和 viewBox，按显式单位或 96 CSS px/in 的换算规则处理无物理单位的尺寸，并在导入预览显示换算。
- SVG 屏幕坐标转换到 Y 向上的建模坐标；曲线方向和孔洞包含关系重新验证。
- 三次/二次贝塞尔路径转换为等价 B 样条；椭圆弧保留弧参数；非均匀缩放圆应转换为椭圆而非保持错误半径。
- 只解析白名单几何和属性；忽略脚本、事件、外部资源、foreignObject、滤镜和文本，给出忽略报告；导入内容不得注入网站 DOM。
- 区域使用外边界和孔洞导出；默认不导出网格、选择高亮或操作手柄。选择“含尺寸标注”时才输出展示用文字。

文档最多 20,000 个输入几何对象、100,000 个控制点、10,000 个约束和 5,000 个特征，单个导入文件不大于 50 MiB。生成后总边数最多 100,000；超限时拒绝该事务并保留原模型。限制用于明确资源边界，不代表所有上限模型都满足交互性能指标。

**16．性能、交互稳定性和失败恢复**

以下指标是开发验收目标，不是当前网站的实测结果。验收报告必须记录设备型号、CPU、内存、浏览器精确版本、屏幕尺寸、设备像素比、冷/热启动及网络条件。

| 场景 | 规定数据量 | 验收目标 |
|---|---|---|
| 缩放和平移 | 1,000 条可见直线/圆弧，不连续重算拓扑 | 桌面连续 10 秒操作，帧间隔 P95 ≤ 25 ms，无超过 200 ms 的界面停顿 |
| 点选和吸附 | 1,000 条几何对象 | 桌面输入至高亮反馈 P95 ≤ 50 ms |
| 参数修改 | 单一连通草图，200 个约束 | 桌面求解加预览 P95 ≤ 150 ms；使用包含尺寸和相切的固定测试草图 |
| 成面及布尔 | 500 条有效边、50 个孔洞的固定样例 | 桌面单次 P95 ≤ 2 秒，期间界面仍可响应取消 |
| 本机保存 | 5,000 个对象和完整约束/特征记录 | 保存移出交互热路径，完成状态正确，无明显输入阻塞 |
| 手机查看和基础编辑 | 300 个对象、50 个约束的固定样例 | 缩放平移帧间隔 P95 ≤ 40 ms，触摸目标不串操作 |
| 反复进入退出 | 连续打开和关闭建模工作区 20 次 | 不重复绑定事件，不残留计时器或 Worker，内存不持续线性增长 |

性能模型至少执行一次预热和五次正式测量；交互延迟至少采集 100 次事件。超过性能目标时如实标记不通过并优化，不换成更简单模型后称原样例通过。

加载要求：现有非建模页面不下载建模 WASM；进入后先显示可响应的工作区及加载状态。内核未就绪时禁用依赖其能力的操作，不展示假成功预览。首次下载与编译耗时分开报告；不承诺受网络影响的统一秒数。离线缓存命中可继续打开本机草稿，首次未缓存时清楚提示无法加载内核。

渲染要求：屏幕曲线离散误差不大于 0.5 CSS px，导出和拓扑不使用该显示折线；线宽和手柄尺寸在缩放时保持易读；禁用主页面流场渲染。切换标签页时暂停无意义刷新；没有变化时不运行持续重绘循环。

错误恢复要求：输入非法、约束失败、拓扑失败、导入失败、磁盘草稿写入失败和 Worker 退出都有明确提示。任何失败不得清空当前模型。选中的无效区域不能导出为有效几何；项目文件可以保存诊断所需的源草图。异常恢复后的文档必须重新校验，不能只隐藏错误提示。

**19．测试执行与完成检查**

需要新增以下项目脚本；脚本名称属于实现交付要求，当前仓库不一定已存在：

```text
npm run test:modeling:unit       数值、数据、命令、参数与迁移
npm run test:modeling:kernel     真实约束和几何内核的集成契约
npm run test:modeling:e2e        实际浏览器完整绘制和编辑
npm run test:modeling:fixtures   M01–M14 与错误模型校验
npm run test:modeling:perf       固定场景的性能采集
npm run typecheck               项目类型检查
npm run build                   生产构建
```

保留运行相关旧测试：`test:sketch`、`test:cfd-workbench`、`test:solvers`。对首页、知识库和现有工具入口执行浏览器回归；不因本次任务无关而修改其业务逻辑。

几何测试不能只比较绘制出来的像素；必须检查端点、半径、参数范围、约束残差、有效区域、面积和孔洞数量。文件测试不只比较对象数量，还应逐项比较支持的几何参数和引用关系。

浏览器测试至少覆盖桌面 Chromium、Firefox、WebKit 的关键操作，并在 Android Chrome 和 iOS Safari 中检查真实触摸行为；仿真设备可以补充布局测试，不能替代所有真机结论。无法取得某个实际设备时，在报告写明未验证，不能宣称该设备通过。

约束验证除了读取求解器状态，还要用独立几何测量核对：水平线 Y 差、垂直向量点积、平行向量叉积、尺寸误差、圆弧半径和切线方向。复杂模型完全约束判定不能只用“变量数减约束条数”。

依赖绑定的契约测试至少覆盖：线/圆/椭圆/样条建立；直线和圆弧交点；线框成面及孔洞；矩形差集；曲线偏移；拓扑有效性；来源映射；约束增删；圆弧内部关系；求解失败后恢复；内核资源回收。发现封装缺失时补齐适配或固定版本的绑定，并再次验证，不缩减本文范围。

验收报告每条记录至少包含：AT 编号、对应功能编号、模型编号、环境、操作步骤、预期值、实际值、判定和证据位置。数值记录需要单位及容差；截图用于界面验证，视频用于连续交互，日志用于错误和性能，三者不能相互冒充。

所有必需项目通过才标记完整交付。仍有失败项时继续修复并更新同一份报告；不能将失败项目改名为“未来优化”后宣布完成。
